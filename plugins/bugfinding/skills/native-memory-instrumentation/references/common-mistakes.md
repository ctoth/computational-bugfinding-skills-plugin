# Common mistakes

| WRONG | RIGHT | Why | Primary evidence |
|---|---|---|---|
| Enable every sanitizer in one binary. | Select compatible property-specific builds. | The driver pairs Address with "SanitizerKind::Thread \| SanitizerKind::Memory" as incompatible, and Leak likewise. | [Clang driver, IncompatibleGroups](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/clang/lib/Driver/SanitizerArgs.cpp) |
| The driver is instrumented, so its prebuilt FFI library is covered. | Verify actual library and shadow-propagation boundaries. | MSan "requires that all program code is instrumented" or it "may result in false reports"; ASan's compile-time instrumentation "does not handle system libraries". | [MSan, Handling external code](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/clang/docs/MemorySanitizer.md), [ASan paper §5.2](https://www.usenix.org/system/files/conference/atc12/atc12-final39.pdf) |
| A zero exit means no undefined behavior. | Preserve recovered diagnostics and selected check mode. | For most checks UBSan "prints a verbose error report and continues execution". | [UBSan, Usage](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/clang/docs/UndefinedBehaviorSanitizer.md) |
| No leak report before forced termination means no leak. | Record whether the selected scan actually completed. | LSan's "extra leak detection phase" comes at the end of the process, and Memcheck searches "when the client program finishes". | [LSan, Introduction and Programmatic Disabling](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/clang/docs/LeakSanitizer.md), [Memcheck §4.3](https://valgrind.org/docs/manual/mc-manual.html) |
| All displayed leaks change the exit status. | Record full-scan and selected error-kind policy separately. | `--errors-for-leak-kinds` sets "the leak kinds to count as errors"; `--show-leak-kinds` only sets what is shown. | [Memcheck §§4.2.10–4.3](https://valgrind.org/docs/manual/mc-manual.html), [core §2.7.3 Error-related Options](https://valgrind.org/docs/manual/manual-core.html) |
| Add ignore rules until the run is clean. | Keep real initialization evidence and record each explicit omission. | Under an MSan ignorelist "all values loaded from memory will be considered fully initialized". | [MSan, Ignorelist](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/clang/docs/MemorySanitizer.md) |
| ASan covers arbitrary managed Windows methods. | Establish native translation-unit/module coverage and mixed-mode lifetime. | C++/CLI code "isn't guaranteed to receive ASan load and store instrumentation". | [MSVC known issues, ASan support for C++/CLI is experimental](https://raw.githubusercontent.com/MicrosoftDocs/cpp-docs/f29e25fb8f05bb38cf0246476b5c1fc92bf33876/docs/sanitizers/asan-known-issues.md) |
| A smaller crash is necessarily the original native defect. | Preserve valid-call state, allocator conditions and selected witness. | Changing allocation churn changes detection: "a use-after-free may not be detected" after a large allocate/free burst. | [ASan paper §3.5](https://www.usenix.org/system/files/conference/atc12/atc12-final39.pdf) |
