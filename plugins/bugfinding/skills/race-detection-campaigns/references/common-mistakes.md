# Common mistakes

| WRONG | RIGHT and source | Why |
|---|---|---|
| Increase goroutines while never reaching close/reload. | Design the real lifecycle overlap; historical publication/reference-count bugs required those paths ([TSan 2009, §§6.3–7.1, pp.67–69](https://static.googleusercontent.com/media/research.google.com/en//pubs/archive/35604.pdf)). | The detector "can't find races in code paths that are not executed" ([Go guide, How To Use](https://raw.githubusercontent.com/golang/website/a8b66266e226994e2ead51317bace3ee83cedab9/_content/doc/articles/race_detector.html)). |
| Serialize every target operation with a harness mutex. | Coordinate phases without erasing competition ([TSan 2009, §6.5, p.69](https://static.googleusercontent.com/media/research.google.com/en//pubs/archive/35604.pdf)). | Excessive synchronization "may hide real races from data race detectors". |
| Treat a race-enabled Go host as plugin/native coverage. | Inspect actual plugin limitations and native build flags ([plugin](https://raw.githubusercontent.com/golang/go/dcc06a82727b447270b1a58cc5f86b49736e317c/src/plugin/plugin.go), [cgo path, lines 3553–3560](https://raw.githubusercontent.com/golang/go/dcc06a82727b447270b1a58cc5f86b49736e317c/src/cmd/go/internal/work/exec.go)). | Plugins "are poorly supported by the Go race detector", and cgo gets no automatic TSan flag. |
| Union every published/development architecture list. | Use the selected compiler/runtime; the inspected source and article differ ([platform source](https://raw.githubusercontent.com/golang/go/dcc06a82727b447270b1a58cc5f86b49736e317c/src/internal/platform/supported.go), [guide](https://raw.githubusercontent.com/golang/website/a8b66266e226994e2ead51317bace3ee83cedab9/_content/doc/articles/race_detector.html)). | The source admits `linux/riscv64`, which the article omits; neither is the installed toolchain. |
| Silence a warning by inventing a synchronization annotation. | Establish the actual relation first; detector model knowledge changes findings ([TSan 2009, §5, pp.65–66](https://static.googleusercontent.com/media/research.google.com/en//pubs/archive/35604.pdf)). | Annotations such as `ANNOTATE_BENIGN_RACE` and ignore regions remove observations rather than prove synchronization. |
| Call adaptive native delay a Go or replayable scheduler. | Verify runtime support, Go exclusion and time-derived seeds ([initialization, lines 777–779](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/compiler-rt/lib/tsan/rtl/tsan_rtl.cpp), [seed, line 271](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/compiler-rt/lib/tsan/rtl/tsan_adaptive_delay.cpp)). | Init is under `#if !SANITIZER_GO` and seeds with `SetRandomSeed(NanoTime())`. |
| Treat Helgrind exit 0 as no report, or a lock-order warning as an observed hang. | Parse retained diagnostics and distinguish result classes ([core exit options](https://valgrind.org/docs/manual/manual-core.html), [Helgrind §7.3](https://valgrind.org/docs/manual/hg-manual.html)). | With default `--error-exitcode=0` Valgrind returns the target's own status; a lock cycle is "a potential deadlock". |
| Attribute race-only process growth to a Go heap leak. | Check detector auxiliary allocation behavior before attribution ([Go overhead](https://raw.githubusercontent.com/golang/website/a8b66266e226994e2ead51317bace3ee83cedab9/_content/doc/articles/race_detector.html)). | Race-mode `defer`/`recover` allocations "will not show up in the output of" `runtime.ReadMemStats` or `runtime/pprof`. |
