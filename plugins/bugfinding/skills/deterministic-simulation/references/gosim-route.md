# Selected Gosim route

## Applicability before setup

This reference selects neria-cloud/gosim at the pinned sources below; do not mix it with another fork or release. Its admitted compiler families are Go 1.25/1.26, with Linux AMD64/ARM64 and Darwin ARM64 hosts documented in the selected README ([family table](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/internal/buildspec/families_gen.go), [README Technical introduction](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/README.md)). The README also states "Prerelease and development compilers are unsupported.", and its "Current scope of features" Platforms row lists only "Linux AMD64 and Darwin ARM 64", so check the actual host rather than the longer list. A module's minimum Go version alone is not an admission check. Inspect the actual target toolchain, CGO and dependencies; this evidence does not establish Go 1.27 or Windows compatibility. Replay is tied to the exact compiler patch: "a family policy does not promise replay across different patches" ([README, Technical introduction; Current scope of features; Development and test reports](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/README.md)).

Application loading explicitly sets CGO_ENABLED=0 and selects simulation source/configuration; source translation redirects concurrency and state into the controlled runtime ([loader](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/internal/translate/load.go), [architecture](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/design.md)). The engine uses "cooperative coroutine scheduling, deterministic channels/maps, a seeded scheduler and simulated time" ([architecture, Engine](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/design.md)); do not advertise ordinary native execution or exhaustive weak-memory checking. If a compiler contract or dependency is unsupported, retain that limit and choose a fitting method; do not downgrade production or bypass an unexpected diagnostic.

## Configured execution

Prefer an existing compatible integration. The selected README documents module dependency setup and a launcher build using its internal-linkname mode; inspect that exact recipe and project ownership before an authorized setup change. For a configured launcher and actual named test, these source-read shapes select features and bounded seed choices ([README, deterministic test and debugging](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/README.md)):

```text
./.gosim/gosimtool test -features rt,fs,net -seeds 1-20 -run TestScenario .
./.gosim/gosimtool debug -features rt,fs,net -package . -test TestScenario -seed 1 -step 11
```

Replace the name/seed range/step with actual evidence and budget. The README states "Debug requires Delve and supports `-headless`."; a seed range bounds selected seeds, not host CPU time. Recheck selected command help rather than infer an installed release matches this source ([README](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/README.md)). No command here is a tested integration or an instruction to install dependencies automatically.

Feature selection "is immutable before application initialization". NewMachine is unstarted: configure relevant services, call Start, then check every control result. "`Stop` flushes modeled writes; `Crash` retains a crash outcome. `Restart` creates a fresh epoch with new globals"; termination "cancels its goroutines without executing their pending defers" ([architecture](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/design.md), [feature inventory](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/features.md), [machine controls](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/machine_sim.go)). Preserve the distinction when testing durability; a clean return from a machine main is not the desired abrupt failure.

## Choose faults the model actually exposes

| Needed dimension | Selected capability and boundary |
|---|---|
| Network | Public Partition/Repair controls validate IPv4 links with `Both` or `Forward` direction; SetLinkPolicy sets per-link latency and loss (failure/repair probabilities) and ResetLinkPolicy restores global inheritance. The documented model supports TCP but excludes DNS, UDP, IPv6, TLS execution and arbitrary packet reordering ("There is no public reordering policy"); "Streams have acknowledgement and keepalive timers but no TCP retransmission", so repairing a link may require application reconnection ([controls](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/net/control_sim.go), [feature inventory](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/features.md)). |
| Storage failure | SetCrashMode selects "`DurableOnly` or `SamplePending` behavior for non-fsynced operations"; SetSyncFault configures "bounded crash probabilities around sync"; SetReadOnly makes writes return `EROFS`; `fs.Config.CapacityBytes` makes over-capacity writes fail with `ENOSPC`. "General random I/O errors, silent corruption, and injected short reads are not exposed as controls" ([controls](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/fs/control_sim.go), [feature inventory](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/features.md)). |
| Recovery alternatives | CrashStates takes MaxStates, Next yields retained snapshots, and Restore applies one to a machine. Close iterator/snapshots according to actual ownership; exhaustion is bounded modeled coverage ([declarations](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/fs/recovery.go), [implementation](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/fs/recovery_sim.go)). |
| Time | The feature inventory supplies virtual timers and "A seeded cooperative scheduler"; "`rt.SetTimeout` bounds simulation time". Simulated time advances only "When no goroutine is runnable", so inspect host CPU/wall interruption separately; a virtual timeout is not shown to stop a busy loop ([features](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/features.md), [architecture, Engine](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/design.md)). |

Retain Seed, Toolchain, Profile, AdapterRevision, RuntimeRevision, Features, host/simulation architecture and BuildDigest/ReplayRevision; the deprecated Certified field is always false ([RunInfo](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/rt/info.go)). Replaying a seed after source, compiler, feature or race-policy changes is a different build-identity experiment: "Toolchain, architecture, source, feature, race or approved build-policy changes define another identity" ([README, A deterministic test](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/README.md)). Host randomness can still escape: Ed25519 "`GenerateKey(nil)` uses native host randomness and is not replay-deterministic" ([architecture](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/design.md)). Selected Gosim is MIT-licensed; that says nothing about a target's complete dependency licensing ([license](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/LICENSE)).
