# Boundaries and oracles

## Select an implementation that actually admits the target

Keep production source as the owner. A simulator may legitimately replace environmental operations, but that model's fidelity is a separate assumption: FoundationDB's paper identifies missed dependencies and weaker-than-assumed OS contracts as blind spots, citing bugs from "the true operating system contract being weaker than it was believed" ([§4 Limitations, p. 9](https://www.foundationdb.org/files/fdb-paper.pdf)). Inspect actual syscall, scheduler, lifecycle and dependency paths before claiming controlled execution.

Distinguish three results: a model-admitted test, a replayed simulated contradiction, and a contract-adjudicated target finding. FDB's simulator uses local assertions, generated-workload invariants and a recoverable-environment progress check; none substitutes automatically for the others ([§4 Test oracles, pp. 8-9](https://www.foundationdb.org/files/fdb-paper.pdf)).

A fitting seam can be translated source, as in Gosim's loader, or a target's existing runtime, as in Flow. Gosim's loader overrides `CGO_ENABLED` to `0`; FDB's client workloads run in the main network thread, and "Using the callback API is therefore required" to keep determinism ([Gosim loader](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/internal/translate/load.go), [FDB Parallelism and Determinism](https://raw.githubusercontent.com/apple/foundationdb/7e7611f8270952a2b1cffd75aa523c4b057afd62/documentation/sphinx/source/client-testing.rst)). An incompatible target is a method-selection result, not a reason to copy its implementation or change its runtime.

## Derive the oracle at a real boundary

For a promised acknowledged-recovery property, retain the acknowledged operation and specified failure model, then observe recovered state. For progress, establish a recoverable regime before requiring it: FDB returns the modeled hardware "to a state in which recovery should be possible", while TigerBeetle heals a quorum core and, for non-core failures, is "making those failures permanent" ([FDB §4 Test oracles, p. 9](https://www.foundationdb.org/files/fdb-paper.pdf), [TigerBeetle liveness account](https://tigerbeetle.com/blog/2023-07-06-simulation-testing-for-liveness/)). Choose the target's actual guarantee; these are different examples, not universal quorum rules.

A mock narrows the observed dependency contract. Antithesis states "There’s no internet access inside the Antithesis environment", so third-party services "need to be deployed alongside it" or uploaded as a mock; passing that environment does not test an omitted external vendor's behavior ([prerequisites, Complete network isolation](https://antithesis.com/docs/faq/prerequisites/)). Keep the substitution explicit rather than treating an unavailable service as successfully tested.

## Complementary evidence

Retain native races/weak memory, real OS/filesystem contracts, external dependencies and performance where the simulation omits them. FDB documents "a combined regime of robust simulation, live performance testing, and hardware-based failure testing", and because simulation runs single-threaded it is "not suitable for testing various multi-threaded aspects of the FDB client", which its real-cluster C API tester covers ([Simulation and Testing](https://raw.githubusercontent.com/apple/foundationdb/7e7611f8270952a2b1cffd75aa523c4b057afd62/documentation/sphinx/source/testing.rst), [API Tester](https://raw.githubusercontent.com/apple/foundationdb/7e7611f8270952a2b1cffd75aa523c4b057afd62/documentation/sphinx/source/client-testing.rst)). Use the corresponding race, crash-consistency, distributed-fault and resource skills for those dimensions; more identical seeds cannot add an absent observer or environment.
