# Common mistakes

| WRONG | RIGHT and source | Why |
|---|---|---|
| “A simulator ran, so every dependency was controlled.” | Inspect actual environmental seams and omissions. FDB's simulation is "unable to test third-party libraries or dependencies" and FDB records weaker OS contracts as a blind spot ([§4 Limitations, p. 9](https://www.foundationdb.org/files/fdb-paper.pdf)). | An uncontrolled path runs natively or not at all, so a pass says nothing about it. |
| “More failures always find deeper bugs.” | Measure reached states; FDB tunes faults to avoid "a small state-space caused by an excessive fault rate", and a recoverable regime is needed for a recovery assertion ([FoundationDB §4, p. 9](https://www.foundationdb.org/files/fdb-paper.pdf)). | Excess faults keep the system in shallow failure states. |
| “Random eventual healing tests persistent progress failures.” | Keep the specific contract's healthy core while "making those failures permanent" outside it where supported ([TigerBeetle, Teaching the VOPR](https://tigerbeetle.com/blog/2023-07-06-simulation-testing-for-liveness/)). | In safety mode "the simulator is guaranteed to restart each replica eventually", erasing the stuck state. |
| “This Gosim module supports any recent Go/compiler/CGO project.” | Verify selected families, platforms and CGO-disabled source loading; choose a different fitting method for unsupported targets ([family table](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/internal/buildspec/families_gen.go), [loader](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/internal/translate/load.go), [README](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/README.md)). | Only families 1.25 and 1.26 are declared, and "Prerelease and development compilers are unsupported." |
| “Graceful Stop and Crash are equivalent recovery controls.” | Preserve actual termination/durability semantics; these use different requests ([machine controls](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/machine_sim.go), [feature inventory](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/docs/features.md)). | "`Stop` flushes modeled writes", so it cannot expose lost unsynced data. |
| “The same seed always replays after a build change.” | Retain full build/replay identity and actual replay evidence ([Gosim RunInfo](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/rt/info.go), [Gosim README](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/README.md), [VOPR seed/commit](https://raw.githubusercontent.com/tigerbeetle/tigerbeetle/68958eb757747d0fc96a79d1f9c2fa6766b67b48/docs/internals/vopr.md)). | Gosim: source, toolchain, feature or race changes "define another identity". |
| “MaxStates exhausted means every filesystem outcome is safe.” | Report the explicit model budget and retained snapshots; bounded enumeration is not real-filesystem exhaustion ([recovery declarations](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/fs/recovery.go), [implementation](https://raw.githubusercontent.com/neria-cloud/gosim/64ac3b2a20806bb4f9470232e12fabdfd5d13852/fs/recovery_sim.go)). | The iterator enumerates outcomes "up to an explicit budget" of a modeled filesystem. |
| “Simulation passed, so performance is fine.” | Keep actual performance and hardware/OS testing complementary ([FDB testing](https://raw.githubusercontent.com/apple/foundationdb/7e7611f8270952a2b1cffd75aa523c4b057afd62/documentation/sphinx/source/testing.rst), [paper §4 Limitations, p. 9](https://www.foundationdb.org/files/fdb-paper.pdf)). | FDB's simulation "is not able to reliably detect performance issues". |
