# Bounded model checking

Choose a supported real component and a falsifiable finite guarantee. Bounded checking converts program constraints and a negated property into a solver query ("we convert C ∧ ¬P into CNF"), and its unwinding assertions "assert that the unwinding bound is actually large enough" ([CBMC paper, §2.1, p.170](https://www.kroening.com/papers/tacas2004.pdf)). Model assumptions and omitted behavior further delimit the conclusion; record them as described below. This skill owns domain/completeness interpretation; use `symbolic-concolic-execution` for path-generation and hybrid-search mechanics.

## Select the actual producer and model

Call the real target from its existing harness or supported entrypoint; preserve initialization and application invariants. Kani says "By far, the best strategy is to follow your testing" and that random-operation property tests "won't be practical to directly port to model checking". Its pure-component route does not establish surrounding I/O behavior: "Kani doesn't model I/O" ([real-code guide, Where is proof valuable / Where is it easier to start](https://raw.githubusercontent.com/model-checking/kani/94253e32fe7ead82c9f1ef842bd9ddc6fae7e8ca/docs/src/tutorial-real-code.md)). Inspect bytecode, library summaries, missing bodies and enabled configuration before treating an abstracted call as the actual producer; JBMC provides "a simple stub implementation for any function we don't have a bytecode implementation for" ([frontend, generate_function_body](https://raw.githubusercontent.com/diffblue/cbmc/826c1c739051aa1c2dd8846282e12691db1cee35/jbmc/src/jbmc/jbmc_parse_options.cpp)).

Record input/state ranges, operation/container sizes, loop/recursion bounds, ABI and environment assumptions separately. CBMC accepts source or a linked GOTO binary and exposes target platform configuration; `--arch` "defaults to the host architecture", which is not evidence of the intended target semantics ([manual, Description and Platform options](https://raw.githubusercontent.com/diffblue/cbmc/826c1c739051aa1c2dd8846282e12691db1cee35/doc/man/cbmc.1)). Read [bounds and models](references/bounds-and-models.md).

## Establish meaningful reach and sufficient bounds

Check that legal setup reaches the asserted property. An unsatisfiable assumption means "the model checking step will pass vacuously"; CBMC offers a separate `--cover assume` observation to locate the assumption that empties the search ([assumptions, Modeling with Assumptions and Coverage](https://raw.githubusercontent.com/diffblue/cbmc/826c1c739051aa1c2dd8846282e12691db1cee35/doc/cprover-manual/modeling-assumptions.md)). For Kani, "Check the coverage report using `--coverage -Z source-coverage`"; incomplete coverage is "usually because you've assumed too much" ([real-code guide, Your first proof](https://raw.githubusercontent.com/model-checking/kani/94253e32fe7ead82c9f1ef842bd9ddc6fae7e8ca/docs/src/tutorial-real-code.md)). Use `harness-sensitivity` for representative healthy/wrong controls.

Retain completeness checks. A failed unwinding assertion is evidence about the chosen bound, not the separate product assertion; partial-loop paths can be spurious ([unwinding guide](https://raw.githubusercontent.com/diffblue/cbmc/826c1c739051aa1c2dd8846282e12691db1cee35/doc/cprover-manual/cbmc-unwinding.md)). Kani states "Verification results are sound only if all unwinding assertions pass" ([soundness, Bounded verification](https://raw.githubusercontent.com/model-checking/kani/94253e32fe7ead82c9f1ef842bd9ddc6fae7e8ca/docs/src/soundness.md)). In the pinned CBMC source, unwinding assertions are part of the checks "enabled by default in v6.0+" and are switched off by `--no-unwinding-assertions` or `--no-standard-checks` ([cbmc_parse_options.cpp, set_default_analysis_flags](https://raw.githubusercontent.com/diffblue/cbmc/826c1c739051aa1c2dd8846282e12691db1cee35/src/cbmc/cbmc_parse_options.cpp)). Increase the missing dimension justified by evidence; do not disable a check or assume the desired result to make a run pass.

## Run a fitting finite lane

Use the selected tool/version's actual prerequisites, supported target and help. Read [conditional CBMC/JBMC/Kani operation](references/tool-recipes.md) for source-native commands, setup and result modes. Its numbers are illustrative allocations, not defaults. Keep whole-job resource limits separate from semantic bounds; a truncated search does not become complete because its process ended.

Inspect individual results and coverage. Kani distinguishes failed, unreachable and undetermined checks; a `SUCCESS` property "may hold _vacuously_", and an unreachable or unsatisfiable cover property "may indicate an incomplete proof" ([verification results, Check results and Cover property results](https://raw.githubusercontent.com/model-checking/kani/94253e32fe7ead82c9f1ef842bd9ddc6fae7e8ca/docs/src/verification-results.md)). Neither a solver timeout nor an unsupported model operation is an exercised healthy property.

## Preserve and replay the counterexample

Retain exact producer/harness/model/checker/build identity, assumptions, dimensions/bounds, raw results, trace and concrete inputs/state. Relate the trace to the real assertion before proposing cause; the original CBMC interface steps through a trace "also backward, giving the user the ability to determine more easily the causes of the error" ([CBMC paper, §3, p.171](https://www.kroening.com/papers/tacas2004.pdf)). Read [counterexamples and replay](references/counterexamples-and-replay.md) before interpreting native confirmation: Kani playback "does not generate unit tests for failing non-panic checks (e.g., UB checks)" and requires "the same Kani version to generate the test and to playback" ([playback, Limitations](https://raw.githubusercontent.com/model-checking/kani/94253e32fe7ead82c9f1ef842bd9ddc6fae7e8ca/docs/src/reference/experimental/concrete-playback.md)).

Return the exact checked guarantee/domain, completed or unresolved bounds, per-property result, model omissions, actual native replay and evidence paths. Preserve model-only findings explicitly. Use `failure-reduction` and `evidence-based-triage` for their separate concerns; read [common mistakes](references/common-mistakes.md) for misleading green/red outcomes. Invocation adds no installation, target-change, external-publication or spending authority.
