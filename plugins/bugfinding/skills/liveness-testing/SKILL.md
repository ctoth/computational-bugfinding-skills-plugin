# Liveness testing

Find a real pending obligation and an admissible execution that prevents its required progress. Fairness and environmental enabledness determine whether apparent nontermination is meaningful; a long run alone is weaker evidence. CHESS reduces liveness to termination "under all fair interleavings" and flags nontermination only by "setting an abnormally high bound on the length of the execution" ([CHESS, §§4.2, 4.3 and 4.5](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/osdi2008-CHESS.pdf)).

## Define the progress claim

Read the actual producer, enabled configuration and completion/cancellation semantics. Name the admitted request or recovery phase, its start, and every permitted discharge event. Choose the monitor from that contract: Coyote's task helper checks that a task "eventually completes execution successfully", so it does not implement a contract allowing cancellation merely because both are terminal task states ([task helper, IsSatisfied](https://raw.githubusercontent.com/microsoft/coyote/2202e75a861f4e8a63149366c2e41ea21d73ae54/Source/Core/Specifications/Monitors/TaskLivenessMonitor.cs)). Read [progress contracts](references/progress-contracts.md) for concrete cases.

State the scheduler, delivery, availability and retry assumptions the target actually promises. Preserve a recoverable regime where progress is required: FoundationDB returns modeled hardware "to a state in which recovery should be possible" before checking recovery ([FDB, §4 Test oracles, p.9](https://www.foundationdb.org/files/fdb-paper.pdf)), and TigerBeetle heals a healthy core while "making those failures permanent" outside it, exposing failures that repeated healing/restarts erase ([TigerBeetle, Teaching the VOPR](https://tigerbeetle.com/blog/2023-07-06-simulation-testing-for-liveness/)). Do not invent eventual delivery or a deadline to make the claim decidable; TigerBeetle's own property holds only "if the operating environment is sufficiently healthy" ([TigerBeetle, introduction](https://tigerbeetle.com/blog/2023-07-06-simulation-testing-for-liveness/)).

## Choose a fitting search and observer

Use existing runtime/control seams for actual work; use an existing temporal model only with an explicit mapping to implementation state/actions. TLC distinguishes a fairness-bearing behavior specification from the property being checked; its clock example states the fairness condition separately, `LSpec == HC /\ WF_hr(HCnxt)` ([LiveHourClock, LSpec](https://raw.githubusercontent.com/tlaplus/tlaplus/d8fb231de4e4b5d02c1b2ed1ac759c086f694021/tlatools/org.lamport.tlatools/test-model/examples/SpecifyingSystems/Liveness/LiveHourClock.tla)). Detailed scheduling and environmental control belong to `schedule-exploration` and `deterministic-simulation`; read [runtime and model routes](references/runtime-and-model-routes.md) for supported operation.

Spend compute on obligation-relevant sequences, interleavings, retry state and admissible persistent faults rather than a higher fault rate; FoundationDB tunes fault distributions "to avoid driving the system into a small state-space" ([FDB, §4 Fault injection, p.9](https://www.foundationdb.org/files/fdb-paper.pdf)). Preserve the state that causes nonprogress instead of resetting it out of the experiment; TigerBeetle's historical repair resonance went undetected "when replica A is restarted and the retry counter is reset" ([TigerBeetle, Resonance](https://tigerbeetle.com/blog/2023-07-06-simulation-testing-for-liveness/)). Use `stateful-property-testing` for dependent workload construction and `bugfinding-campaign` for allocation.

## Interpret the witness before attributing a bug

Separate healthy idle quiescence, exhausted search, heuristic temperature, promised deadline violation, supported deadlock evidence and a fair temporal-model counterexample. Coyote reports a monitor still hot when a test terminates as a liveness bug "at the end of program execution", but a long hot run only as a "potential liveness bug": it checks temperature when `this.Scheduler.IsIterationFair` and only increments a hot monitor's counter ([Coyote runtime, CheckLivenessErrors and CheckLivenessThresholdExceeded](https://raw.githubusercontent.com/microsoft/coyote/2202e75a861f4e8a63149366c2e41ea21d73ae54/Source/Core/Runtime/CoyoteRuntime.cs), [Monitor, IsLivenessThresholdExceeded](https://raw.githubusercontent.com/microsoft/coyote/2202e75a861f4e8a63149366c2e41ea21d73ae54/Source/Core/Specifications/Monitors/Monitor.cs)). Go synctest observes durable blocking rather than enumerating schedules; when every bubble goroutine is durably blocked and no fake-time advance helps, "there is a deadlock and [Test] panics" ([synctest, Time and Blocking](https://raw.githubusercontent.com/golang/go/dcc06a82727b447270b1a58cc5f86b49736e317c/src/testing/synctest/synctest.go)). Read [witnesses and replay](references/witnesses-and-replay.md).

Keep obligation identity, admissible environment, actual producer/wait dependencies, observer state, choices, tool/build/configuration and bounds with the original trace. Reduce the workload and choices while retaining those premises; CHESS documents environmental interference and imperfect replay as limits on observed enabledness and search, handled "at the cost of the exhaustiveness of the search" ([CHESS, §4.2](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/osdi2008-CHESS.pdf)). Use `failure-reduction` and `evidence-based-triage` for their separate mechanics.

Return the promised progress, reached pending work, admitted assumptions, observed failure and replay evidence, tested scope and unresolved alternatives. A TLC exploration result is incomplete until the required final liveness check completes; the checker's own comment reads "Always check liveness properties at the end" ([ModelChecker, modelCheck](https://raw.githubusercontent.com/tlaplus/tlaplus/d8fb231de4e4b5d02c1b2ed1ac759c086f694021/tlatools/org.lamport.tlatools/src/tlc2/tool/ModelChecker.java)). A model witness still needs implementation correspondence; TLC exports and loads traces "to support model-based testing and trace validation" ([USE, Model-Checking with TLC](https://raw.githubusercontent.com/tlaplus/tlaplus/d8fb231de4e4b5d02c1b2ed1ac759c086f694021/USE.md)). For source-backed corrections to misleading shortcuts, read [common mistakes](references/common-mistakes.md).

Invocation preserves existing execution authority; it does not grant target edits, installations, external fault injection or publication.
