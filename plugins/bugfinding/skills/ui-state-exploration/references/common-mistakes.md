# Common UI state exploration mistakes

- **Wrong:** Count a completed crawl as a test. **Better:** Attach oracles to every new state; "just running CRAWLJAX would correspond to conducting a smoke test" ([Mesbah et al., TSE 2012, p.50](https://people.ece.ubc.ca/amesbah/resources/papers/tse11.pdf)).
- **Wrong:** Add broad normalizers until state differences disappear. **Better:** One named normalizer per difference, scoped by a precondition, and inspect what it removed; "Using only the generic comparators would result in a false negative, namely the leading-zero bug" ([Roest et al., ICST 2010, p.134](https://people.ece.ubc.ca/amesbah/resources/papers/icst10.pdf); [TSE 2012, p.40](https://people.ece.ubc.ca/amesbah/resources/papers/tse11.pdf)).
- **Wrong:** Store positional selectors or `[ref=eN]` as edge identity. **Better:** Role and accessible name, resolved again after reload; a positional locator can select "a similar element", causing "a transition to a different state than expected" ([ICST 2010, p.129](https://people.ece.ubc.ca/amesbah/resources/papers/icst10.pdf)), and refs "resolve against the latest snapshot taken in the element's frame" ([Playwright Page API](https://raw.githubusercontent.com/microsoft/playwright/v1.65.0/docs/src/api/class-page.md)).
- **Wrong:** Settle with `networkidle` or one fixed sleep. **Better:** An app settle predicate plus a stability check; `'networkidle'` is "**DISCOURAGED**" ([Playwright params](https://raw.githubusercontent.com/microsoft/playwright/v1.65.0/docs/src/api/params.md)), "an incomplete DOM state could be compared with a complete state" ([ICST 2010, p.135](https://people.ece.ubc.ca/amesbah/resources/papers/icst10.pdf)), and a fixed wait is slow or unsafe ([Mesbah et al., TWEB 2012, p.27](https://doi.org/10.1145/2109205.2109208)).
- **Wrong:** Rely on auto-wait and retrying assertions when the suspected bug is a transient state or a too-early click. **Better:** One-shot reads of the settled key, and labelled early actions or schedule control; Playwright will click "regardless of when the [`method: Locator.click`] call was made", and assertions wait "until the condition is met" ([Playwright actionability](https://raw.githubusercontent.com/microsoft/playwright/v1.65.0/docs/src/actionability.md)).
- **Wrong:** Reuse one browser context and reload to reset. **Better:** A new context per path, with IndexedDB included when seeding saved state; cookies broke Crawljax's reset ([TWEB 2012, p.26](https://doi.org/10.1145/2109205.2109208)), contexts each have "its own local storage, session storage, cookies etc." ([Playwright browser contexts](https://raw.githubusercontent.com/microsoft/playwright/v1.65.0/docs/src/browser-contexts.md)), and "IndexedDB is not included in the snapshot by default" ([Playwright auth](https://raw.githubusercontent.com/microsoft/playwright/v1.65.0/docs/src/auth.md)).
- **Wrong:** Reset only the browser. **Better:** Reset or restore server state per path; Roest et al. needed a database restore because a delete works only the first time ([ICST 2010, p.135](https://people.ece.ubc.ca/amesbah/resources/papers/icst10.pdf)); ATUSA's plugin types include a back-end reset after the initial URL is (re)loaded, and TUDU used a per-run SQL reset ([TSE 2012, pp.44, 48](https://people.ece.ubc.ca/amesbah/resources/papers/tse11.pdf)).
- **Wrong:** Let the explorer click everything. **Better:** Exclude logout, delete and external links unless that path is the target; ATUSA excludes elements that "can cause problems (delete items or log the user out)" ([TSE 2012, p.39](https://people.ece.ubc.ca/amesbah/resources/papers/tse11.pdf)), and its studies excluded delete links and log-out ([TSE 2012, pp.47-48](https://people.ece.ubc.ca/amesbah/resources/papers/tse11.pdf)).
- **Wrong:** Check only the DOM. **Better:** Also page errors, unhandled rejections, console errors and network status; two seeded faults "were silently swallowed by the JAVASCRIPT engine and did not affect the DOM" ([TSE 2012, p.48](https://people.ece.ubc.ca/amesbah/resources/papers/tse11.pdf)).
- **Wrong:** Detect dead clickables with `requestfailed`. **Better:** Read HTTP status of finished requests; 404 or 503 responses "complete with [`event: Page.requestFinished`] event and not with [`event: Page.requestFailed`]" ([Playwright Page API](https://raw.githubusercontent.com/microsoft/playwright/v1.65.0/docs/src/api/class-page.md)).
- **Wrong:** Treat no `pageerror` as no React error. **Better:** Also check console errors, root error callbacks and the error-boundary fallback; a boundary displays "some fallback UI instead of the part that crashed" ([react.dev Component](https://raw.githubusercontent.com/reactjs/react.dev/7594a2b008489121bdf25f97320d11ac0422510e/src/content/reference/react/Component.md)), and "By default, React will log all errors to the console" ([react.dev createRoot](https://raw.githubusercontent.com/reactjs/react.dev/7594a2b008489121bdf25f97320d11ac0422510e/src/content/reference/react-dom/client/createRoot.md)).
- **Wrong:** Raise depth by default for coverage. **Better:** Raise it on evidence; depth 1 to 2 grew one site from 148 to 1,071 states and another from 145 to 1,234 ([TWEB 2012, pp.18, 20](https://doi.org/10.1145/2109205.2109208)), and depth 3 exceeded 60 minutes without changing fault detection ([TSE 2012, p.48](https://people.ece.ubc.ca/amesbah/resources/papers/tse11.pdf)).
- **Wrong:** Report heap growth across one revisit of a discovered cycle as a leak. **Better:** Hand the cycle to `resource-complexity-testing`; BLeak requires growth between every consecutive snapshot over 8 round trips by default, and its false positives were objects growing to a threshold or timeout, avoidable by more round trips ([Vilk and Berger, BLeak, PDF pp.5-6, 11](https://raw.githubusercontent.com/plasma-umass/BLeak/2b2db0832ea412fa56683de045420134e3c3aa79/paper.pdf)).
- **Wrong:** Claim the explored graph is the app's state space. **Better:** Report it as one instance with listed blind spots (listener-only elements, repeated-click elements, excluded actions); Crawljax's evaluation concludes that not all states are necessarily reached, and the paper calls the result "an instance" of the state machine ([TWEB 2012, pp.19, 26](https://doi.org/10.1145/2109205.2109208)).
- **Wrong:** Treat a URL-level random crawl, such as chaosbringer's visited-URL queue with random in-page actions, as UI state coverage. **Better:** Count distinct state keys reached; chaosbringer skips entries whose `normalizeUrl(entry.url)` it has visited ([crawler.ts:917-925](https://raw.githubusercontent.com/mizchi/chaosbringer/5f69d89ef300cc1fb213301d7942ab17f28c82be/packages/chaosbringer/src/crawler.ts)), so different UI states at one URL are not distinguished by that queue (inference from the source read).
