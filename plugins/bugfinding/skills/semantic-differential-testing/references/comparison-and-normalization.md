# Comparison and normalization

Choose equality from the target contract, then inspect whether the implemented observer retains that information. Preserve raw observations alongside normalized ones. PostgreSQL's contracts distinguish duplicate elimination from row ordering: "`SELECT DISTINCT` eliminates duplicate rows from the result", and without `ORDER BY` rows come back "in whatever order the system finds fastest to produce" ([PostgreSQL 18 SELECT, Description steps 6–8](https://www.postgresql.org/docs/18/sql-select.html), [§7.5 Sorting Rows](https://www.postgresql.org/docs/18/queries-order.html)).

| Promised result | Comparison design | Information to preserve |
|---|---|---|
| Ordered typed rows | Sequence equality under the promised tie/NULL/collation rules | Every required column, type, duplicate and promised order |
| Unordered rows retaining duplicates | Bag equality | Full rows and each row's multiplicity |
| Distinct unordered values | Set equality | Every distinct value in the contracted projection |
| Scalar/error plus effects | Result/error relation and the promised state/output observation | Error policy and permitted effects, not only printed text |

The table is a design aid, not a claim that one generic comparator implements these relations. Order rules are contract details: in PostgreSQL later sort keys only order "rows that are equal according to the earlier values", "null values sort as if larger than any non-null value" by default, and collation sets "the sort order and character classification behavior" of text ([PostgreSQL 18 §7.5](https://www.postgresql.org/docs/18/queries-order.html), [§23.2 Collation Support](https://www.postgresql.org/docs/18/collation.html)). When order has ties or nondeterministic permitted outcomes, derive the allowed relation explicitly rather than demand one byte-for-byte result. Numerical tolerances need `numerical-oracles`; do not select a global epsilon to make disagreement disappear. SQLancer's helper is a concrete example of fixed choices that belong to its own contract, not a universal rule: `equals` accepts `Math.abs(a - b) < 0.001 * Math.max(Math.abs(a), Math.abs(b)) + 0.001`, the first-column reader strips trailing zeros, and `canonicalizeResultValue` maps `-0.0` to `0.0` ([SQLancer comparator, `equals`, `getResultSetFirstColumnAsString`, `canonicalizeResultValue`](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/src/sqlancer/ComparatorHelper.java)).

## Inspect the real observer and caller

The inspected SQLancer helper reads `result.getString(1)` (first column only), strips trailing zeros ("Remove the trailing zeros as many DBMS treat" them as non-bugs), and checks size plus `HashSet` equality of values; with the `validateResultSizeOnly` option it checks size only. A real MySQL DQP caller uses it for baseline versus hinted and `optimizer_switch` runs. This is an actual partial observation, not proof of a DBMS or SQLancer defect ([comparator, `getResultSetFirstColumnAsString`, `assumeResultSetsAreEqual`](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/src/sqlancer/ComparatorHelper.java), [DQP caller, `check`](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/src/sqlancer/mysql/oracle/MySQLDQPOracle.java)).

Illustrative comparator counterexample: `[a, a, b]` and `[a, b, b]` have equal length and equal distinct sets but different multiplicities. A contract requiring bags needs more information. Conversely, sorting all results can hide a promised-order violation. Validate the observer against the selected guarantee rather than copying a familiar helper ([PostgreSQL 18 SELECT duplicate/order contracts](https://www.postgresql.org/docs/18/sql-select.html)).

Normalize only documented irrelevant differences. Match implementation-defined semantics or restrict the comparison to an appropriate class; do not normalize away a meaningful sign, encoding, identity or effect. Csmith programs "do not generate the same output across compilers" that differ in integer width/representation, signed conversion or signed bitwise results, so it compares "within an equivalence class but not across classes" ([Csmith, §2.6](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf)).

## Preserve distinct outcomes

Record completed comparisons separately from skipped/unsupported cases and missing observations. SQLancer's helper maps selected expected errors or absent results to a skipped check; that does not establish equality ([comparator](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/src/sqlancer/ComparatorHelper.java)). A mismatch remains a candidate until the contract and input validity support attribution; LLVM reports that many suspected compiler bugs "ended up being bugs in the program being compiled, not LLVM." A timeout cannot select the wrong-value implementation: Csmith reports about 10% of its generated programs are "(apparently) non-terminating" and handles them "using timeouts". Agreement cannot exclude shared faults ([Csmith, §2.6](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf), [LLVM 23.1.0 Miscompilations](https://releases.llvm.org/23.1.0/docs/HowToSubmitABug.html#miscompilations)).
