# Semantic differential testing

Compare executions that are legitimately expected to agree, and observe the guarantee being tested. Identical source is insufficient when semantics differ; agreeing implementations can also share a wrong answer, which Csmith calls "an inherent limitation of differential testing without an oracle" ([Csmith, §2.6](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf)).

## Establish comparability before equality

Read the actual producers, enabled configuration, input contract and observer on both sides; a generator built for another target version produces false alarms, as SQLancer warns that it "is specific to a version of the DBMS" ([SQLancer README, Understanding SQL generation](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/README.md)). State the common guarantee and legal input/state domain. Separate implementation-defined choices, unsupported capabilities and invalid-input robustness from ordinary result equivalence: Csmith compares compilers "within an equivalence class but not across classes" of implementation-defined behavior. A compiler disagreement first needs input-validity investigation; LLVM's first step is to "make sure it is not using undefined behavior" ([Csmith, §2.6](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf), [LLVM 23.1.0 Miscompilations](https://releases.llvm.org/23.1.0/docs/HowToSubmitABug.html#miscompilations)).

Establish equivalent logical starting states through existing fixture/reset/API owners; identical physical bytes are not the general definition of equivalent state. For independent cases, re-establish the required state per case. For lifecycle-dependent failures, retain the causal setup prefix instead. Preserve setup alongside the compared operation, as SQLancer's bug log keeps the last query "along with the other statements to set up the database state" ([SQLancer README, Logs](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/README.md)). Read [matched state and effects](references/matched-state-and-effects.md) for batch drift, identities and observation boundaries.

## Observe what the contract promises

Choose typed results, permitted errors and relevant external effects; do not substitute a scalar return or implementation-specific serialization for a world-effect guarantee. Different testing observations cover different properties; SQLite separates anomaly (failure) tests, journal-before-database write checks and "exactly the same answer" optimization comparisons ([SQLite testing, §§3, 8.5 and 9](https://www.sqlite.org/testing.html)). Use `correctness-oracles` for general contract derivation and `crash-consistency-testing` for recovery guarantees.

Read the actual comparison path. SQLancer's inspected MySQL DQP caller uses a first-column string observer with cardinality/set checks; that observation is not complete typed-row bag equality ([DQP caller](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/src/sqlancer/mysql/oracle/MySQLDQPOracle.java), [comparator](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/src/sqlancer/ComparatorHelper.java)). Select sequence, bag or set equivalence from the guarantee: in PostgreSQL, `SELECT ALL` returns all candidate rows "including duplicates", while without `ORDER BY` the row order "must not be relied on"; unspecified order does not erase duplicate counts ([PostgreSQL 18 SELECT, Description step 6](https://www.postgresql.org/docs/18/sql-select.html), [§7.5 Sorting Rows](https://www.postgresql.org/docs/18/queries-order.html)). Read [comparison and normalization](references/comparison-and-normalization.md).

Keep input rejection, expected error, unsupported check, missing/malformed output, resource abort and completed comparison distinct where they affect the conclusion. A skipped comparison is not evidence of agreement; SQLancer's observer throws `IgnoreMeException` for a null result or an expected error, so that case never reaches a comparison ([comparator, `getResultSetFirstColumnAsString`](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/src/sqlancer/ComparatorHelper.java)). Use `harness-sensitivity` to establish that the same observation rejects a representative wrong effect while accepting a healthy pair.

## Search, replay and adjudicate the paired case

Reuse existing generators/runners. Vary state and operations together when required, and compare effects at the selected boundary rather than merely extending a return-only lane. Use `semantic-program-generation` or `stateful-property-testing` for those inputs; use `configuration-differential-testing` for factor selection and `metamorphic-testing` for transformation-relation design. SQLancer and SQLite demonstrate complementary state/program and execution-mode dimensions: SQLancer generates schema, data and "various other kinds of database states" before queries, and SQLite's dbsqlfuzz "mutates both the SQL input and the database file" ([SQLancer README, Test input generation](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/README.md), [SQLite testing, §§4.1.3 and 9](https://www.sqlite.org/testing.html)).

Preserve original inputs, initial state/prefix, both build/configuration identities, raw observations, normalization and replay outcomes. Reduce the paired case while retaining legal preconditions and the selected mismatch; Csmith found that C reducers introduce undefined behavior ("The resulting programs are small but useless."), and SQLancer's manual reduction requires "checking that both queries still produce a different result" ([Csmith, §4](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf), [SQLancer README, Reducing bugs](https://raw.githubusercontent.com/sqlancer/sqlancer/a7d60ee450e6a22ca38599c14e984a49773f4745/README.md)). Use `failure-reduction` for mechanics and `evidence-based-triage` for attribution and grouping.

Report the observed disagreement before assigning fault. Use the governing contract and inspectable evidence to adjudicate; majority output is not ground truth. Csmith still catches problems "by hand as part of verifying the failure-inducing program" and states that a shared incorrect output would go undetected. State what actually completed, what the observer omitted, what reproduced and what remains unresolved ([Csmith, §2.6](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf)). For concrete paired experiments, read [worked cases](references/worked-paired-cases.md); for misleading shortcuts, read [common mistakes](references/common-mistakes.md).
