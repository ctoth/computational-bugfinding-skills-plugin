## Write elle-cli JSON from a Node.js recorder

elle-cli reads JSON with `(json/read-str (slurp filepath) :key-fn keyword :value-fn value-reader)`: keys become keywords, `value-reader` keywordizes only the values of `type` and `f`, and for a `value` that is a non-empty vector whose first element is a non-empty vector starting with a string it keywordizes each micro-operation's first element (comment `;; e.g. {:value [[:append :x 1] [:r :y nil]]}`); nothing else is converted ([cli.clj `value-reader`, `read-json-history`](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/src/elle_cli/cli.clj)). Field meanings follow jepsen.history: `:type` "must be one of `:invoke`, `:ok`, `:info`, or `:fail`", `:time` "is a long: The time since the start of the test, in nanoseconds", processes "are logically singlethreaded", and "users may omit indices" ([jepsen.history README, Operation Structure](https://raw.githubusercontent.com/jepsen-io/history/61d2776c889ad84f7c6922977cf05e8f11970402/README.md)).

The repository's fixtures are one JSON array of operation objects. `rw-register-partial-info.json` starts `{"index":0,"process":0,"type":"invoke","f":"txn","value":[["w","x",1]]}` and ends with an invoke that has no completion ([fixture](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/test/test-data/rw-register-partial-info.json)); a list-append fixture has no `f` and no `time` fields ([fixture](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/test/test-data/list-append-anomaly-g1a-aborted-read.json)). Use `test/test-data/` files as format fixtures: the README's example path `histories/elle/rw-register.json` ([elle-cli README, Usage](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/README.md)) has no file at the inspected commit (repository tree listing, 2026-11-09).

Write operations in the order the recorder observed them; with clients sharing one event loop, append to one array at each invoke and completion (`linearizability-checking` covers Node clocks and promise recording). Elle's `realtime-graph` encodes "a < b if a ends before b begins" and its implementation comment says it will "iterate through the history" ([Elle core.clj `realtime-graph`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/core.clj)), so file order is the realtime evidence: sorting by operation id or writing each invoke next to its completion rewrites it for the default `strict-serializable` model. Write `time`, if used, as integer nanoseconds since test start from `process.hrtime.bigint()` differences, which stay exact as JSON numbers below 2^53. This mapping is this pack's synthesis from the cited sources and has not been executed.

## Conditional command

For a selected compatible existing build and a contract promising serializability:

```text
java -jar ELLE_CLI_JAR --model list-append --consistency-models serializable --cycle-search-timeout 1000 --directory EVIDENCE HISTORY.edn
```

Substitute actual paths/model and choose resource values from the authorized budget. The example's 1000ms is the CLI default and limits "searching a single SCC for a cycle", not total analysis or plot time. Omitting `--consistency-models` checks the default `strict-serializable`, which adds realtime constraints a serializable-only contract does not promise; `--anomalies` defaults to `G0`. The inspected CLI accepts EDN/JSON histories, dispatches frontend/model options and has separate rendering controls (`--plot-format`, `--plot-timeout`, `--max-plot-bytes`) ([cli.clj `opts`, `check-history`](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/src/elle_cli/cli.clj)). This command is source-verified, not an executed compatibility claim.

## Interpret actual analysis

Require the requested file's explicit true/false/unknown result. The CLI exits 1 when any collected result is `false`, and 0 otherwise: unknown-only output, `--help`, a missing `--model` and a run with no history argument all exit 0 without a `false`. Exit 1 is shared with option-parse errors, and exceptions such as a missing file exit 255. In text mode each line is the file path, a tab and the verdict; JSON output prints the analysis without the path, so retain file association yourself when checking multiple inputs ([cli.clj `-main`](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/src/elle_cli/cli.clj)).

Preserve prohibited anomalies, inconclusive searches and already-found evidence independently. `:empty-transaction-graph` and `:cycle-search-timeout` yield `:valid? :unknown`; on a timeout the search keeps a fallback cycle and cycles already found, and a found prohibited anomaly still yields `false` ([txn.clj `unknown-anomaly-types`, `cycle-cases-in-scc`, `result-map`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/txn.clj)). A `true` result only says no anomaly prohibited by the selected models or requested anomalies was found: `result-map` keeps only those anomaly types, and "Elle is not complete: it may fail to identify anomalies which were present in the system under test" ([Elle README, Completeness](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/README.markdown)). Absence of a graph/plot is not a healthy-history proof. Record conversion, graph/search/render cost and an outer resource envelope separately.

For direct Clojure integration, select the matching `elle.list-append/check` or `elle.rw-register/check` API, documented as "your main entry points into Elle", and pass only options supported by that selected version. Retain source/binary/configuration, original/converted history and all inference assumptions ([Elle README, Usage](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/README.markdown), [list_append.clj `check`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/list_append.clj), [rw_register.clj `check`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/rw_register.clj)). Detailed fault generation belongs to `distributed-fault-testing`; schedule control belongs to `schedule-exploration`.
