# Observable dependencies

Choose observations for the missing guarantee, then generate interactions that expose them. These are candidate experiments, not promises that every target supports the proposed observation.

| Observation | What must be justified |
|---|---|
| Traceable append values | They exercise the actual producer and preserve unique write provenance |
| Register/version metadata | The exposed order really constrains committed versions |
| Session/process order | The API promises it and the recorder preserves that session |
| Realtime order | Genuine non-overlap is established, without inventing cross-host clock edges |
| Predicate/range membership | A compatible analyzer consumes queried predicates and membership/absence observations |

Append traceability and additional order evidence expose different dependency information: process order, realtime order and exposed version metadata each add edges, and the paper's model omits predicates ([Elle, §§3, 5 and 9](https://arxiv.org/abs/2003.10554v1)). Current model labels such as `:predicate-read-miss` do not by themselves show that a particular frontend records predicate data; the inspected append frontend rejects anything but `:r`/`:append` micro-operations, and the register docstring defines only `[:r x 1]` and `[:w x 2]` forms ([consistency_model.clj `direct-proscribed-anomalies`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/consistency_model.clj), [list_append.clj `verify-mop-types`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/list_append.clj), [rw_register.clj namespace docstring](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/rw_register.clj)).

**Session extension.** A serializable history may violate a separately promised session order: under serializability "a process can fail to observe its own prior writes, if those writes occurred in different transactions". Preserve actual session identity and use a supported model that checks that promise; the inspected mapping has `:strong-session-serializable` proscribing `:G1-process` and `:G2-process`, and requesting process anomalies adds Elle's process graph. Without the extra guarantee, this is not automatically a defect ([Jepsen, Serializability, Informal](https://jepsen.io/consistency/models/serializable), [consistency_model.clj `direct-proscribed-anomalies`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/consistency_model.clj), [txn.clj `additional-graphs`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/txn.clj)).

**Hidden version order.** Blind overwrites can leave the needed relation unknown. A supported traceable representation or trustworthy exposed commit/version order may improve inference. Register `:transaction-order` is a direct-library option, "A map from completion transaction operation indices in the history to a numeric, total transaction order"; it is not an inspected CLI flag. The same docstring warns "the following three options may not work correctly" for `:sequential-keys?`, `:linearizable-keys?` and `:wfr-keys?`. Their assumptions need actual source/version evidence ([rw_register.clj `check`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/rw_register.clj), [cli.clj `opts`](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/src/elle_cli/cli.clj)).

**Predicate extension.** Recording only returned point keys can omit the absence/membership information required by a range guarantee; serializability itself covers predicates ("operations may act on predicates, like “the set of all cats”"), while the paper "ignores predicates and deals only in individual objects". Select a verified predicate-aware observer or leave that dimension untested; renaming a scan as a point read does not supply the missing observation ([Jepsen, Serializability, Informal](https://jepsen.io/consistency/models/serializable), [Elle, §9](https://arxiv.org/abs/2003.10554v1)).

Measure committed/admitted transaction shapes, informative reads, observed dependency kinds and unknown outcomes. Tune contention, length and key lifetime together where the producer supports them; the current generator exposes `:key-dist`, `:key-count`, `:min-txn-length`/`:max-txn-length` and `:max-writes-per-key` ([txn.clj `wr-txns`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/txn.clj)). In the paper's tests, "fewer writes per object stresses codepaths involved in the creation of fresh database objects, and more writes per object allows the detection of anomalies over longer time periods" ([Elle, §7](https://arxiv.org/abs/2003.10554v1)). Reuse an existing workload owner rather than add a generic history service.
