# History and boundaries

Map source-level publication into the promised logical transactions before recording. A retry may produce multiple attempts; an exception may follow a committed slice. Preserve request/attempt provenance in raw evidence, then justify which effects belong to each checker transaction. Jepsen operation semantics, rather than an exception name, determine outcome classification ([jepsen.history README, Operation Semantics](https://raw.githubusercontent.com/jepsen-io/history/61d2776c889ad84f7c6922977cf05e8f11970402/README.md)).

| Recorded outcome | Required evidence |
|---|---|
| `:ok` | Successful logical operation under the API contract ("*must* logically affect the system") |
| `:fail` | Definite failure with no logical effect ("*must* have no logical effect on the system") |
| `:info` | Effect/completion remains indeterminate ("An `:info` may do either.") |
| Recorder/setup failure | Preserve separately; it does not decide target isolation |

Logical processes are single-threaded; a process that crashes, e.g. "by beginning an `:invoke` followed by an `:info`", "can never invoke an operation again". Preserve matching invocation/completion and original observations when adapting formats ([jepsen.history README, Operation Structure](https://raw.githubusercontent.com/jepsen-io/history/61d2776c889ad84f7c6922977cf05e8f11970402/README.md)). In the Elle paper's tests, when a client thread timed out while committing, "Jepsen spawns a new logical process for that thread to execute" ([Elle, §7](https://arxiv.org/abs/2003.10554v1)).

In a Node.js client, `AbortController` is "A utility class used to signal cancelation in selected `Promise`-based APIs" ([Node v26.13.0 globals.md](https://raw.githubusercontent.com/nodejs/node/18b32a3b1552e199a01f1a8d9fd64aa756d3b75b/doc/api/globals.md)), and `AbortSignal.timeout` aborts with `new DOMException('The operation was aborted due to timeout', 'TimeoutError')` ([abort_controller.js](https://raw.githubusercontent.com/nodejs/node/18b32a3b1552e199a01f1a8d9fd64aa756d3b75b/lib/internal/abort_controller.js)). Aborting stops the client waiting; it does not show the server did nothing. Record a timeout or abort rejection as `:info` unless the contract proves no effect. If the original promise settles later, keep that as raw evidence rather than a second completion, and continue that client under a fresh process id (this pack's mapping from the semantics above; not executed).

Validate initialization and types against the actual frontend. Register inference orders `nil` before other versions ("We assume the initial state of every key is `nil`"); an existing non-nil state needs a faithful representation. Append invocation values must be unique per key; preserve repeated/intermediate micro-operations inside the real transaction ([rw_register.clj `initial-state-version-graphs`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/rw_register.clj), [list_append.clj `verify-unique-appends`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/list_append.clj)).

Illustrative control: a write commits, loses its response and is retried. Retain raw attempt identity and evidence of publication; compare mappings that preserve possible effects. Marking the first attempt aborted or counting both attempts as new successful requests can change the history's meaning: `:fail` asserts no logical effect, and the paper notes duplicate writes "can occur when a client or database retries an append operation" ([jepsen.history README, Operation Semantics](https://raw.githubusercontent.com/jepsen-io/history/61d2776c889ad84f7c6922977cf05e8f11970402/README.md), [Elle, §6.1](https://arxiv.org/abs/2003.10554v1)). Establish the real idempotency/transaction contract before selecting either mapping. This is an experiment design, not an observed defect.

Exercise healthy and known-violating recordings through the same converter. Preserve malformed input, missing observations and checker-unknown separately; append validation throws an error map with `:valid? :unknown` for "operations other than appends or reads" or a value appended to one key more than once, before anomaly analysis ([list_append.clj `verify-mop-types`, `verify-unique-appends`, `preprocess`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/list_append.clj)). Sensitivity execution belongs to `harness-sensitivity`.
