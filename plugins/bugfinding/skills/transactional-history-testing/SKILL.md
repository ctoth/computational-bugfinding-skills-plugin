# Transactional history testing

Choose a promised isolation model and observations that can refute it. Append traces reveal version order that overwritten registers can hide: "the version resulting from a blind write carries no information about the previous version", so adding more blind writes adds no version-order evidence ([Elle, §3](https://arxiv.org/abs/2003.10554v1)). Read [observable dependencies](references/observable-dependencies.md) when choosing the workload.

## Establish the actual transaction boundary

Read the public producer, effective mode, initial state, retry path and publication points. Keep logical requests, physical attempts and committed transactions distinct. Jepsen histories distinguish `:ok`, `:fail` ("*must* have no logical effect on the system") and `:info` ("the operation either may or may not have completed"); a transport failure must not become a definite abort without supporting evidence ([jepsen.history README, Operation Structure and Operation Semantics](https://raw.githubusercontent.com/jepsen-io/history/61d2776c889ad84f7c6922977cf05e8f11970402/README.md)). Use [history and boundaries](references/history-and-boundaries.md) for mapping and controls.

Preserve micro-operation order, write provenance and the selected frontend's assumptions. List-append checks reject micro-operations other than reads and appends and require that "every invoke appending a value to a key chose a unique value"; register inference assumes unique writes and that "the initial state of every key is `nil`" ([list_append.clj `verify-mop-types`, `verify-unique-appends`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/list_append.clj), [rw_register.clj namespace docstring, `initial-state-version-graphs`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/rw_register.clj)). Validate conversion through the real recorder, with a healthy case and a justified violation; use `harness-sensitivity` for that experiment.

## Search a missing observation or interaction

Inventory existing workloads before adding another lane. If ordinary concurrent transactions and recorder controls already exist, investigate an uncovered guarantee or dependency: supported session/realtime order, exposed version provenance, short/long key lifetimes, or a predicate-aware observation. Require the actual contract and a compatible analyzer. The paper adds process, realtime and version-metadata dependencies beyond value inference and states "Our approach ignores predicates"; the current model mapping lists `:predicate-read-miss` under PL-3, so that historical exclusion does not establish the limits of every newer extension ([Elle, §§5 and 9](https://arxiv.org/abs/2003.10554v1), [consistency_model.clj `direct-proscribed-anomalies`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/consistency_model.clj)).

Vary contention, read/write patterns, transaction lengths and lifetimes according to useful observed dependencies, not raw transaction count. Existing Elle generators expose `:key-dist`, `:key-count`, transaction length and `:max-writes-per-key`, producing "a variety of short-lived and long-lived keys in a single test"; keep generator choices and admitted/committed operations visible ([txn.clj `wr-txns`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/txn.clj), [Jepsen CHANGELOG, 0.3.12 New Features](https://raw.githubusercontent.com/jepsen-io/jepsen/6766ba09682bcb668d44c025e687dd8b1616e8a2/jepsen/CHANGELOG.md)). Use `stateful-property-testing` for dependent operations and `schedule-exploration` for controlled choices.

## Run and interpret the selected checker

Read [Elle operation](references/elle-operation.md) for an existing JVM/CLI integration, exact option scope, artifact dependencies and result handling. Select the actual promised model: serializability "does not impose any real-time, or even per-process constraints", while strict serializability adds realtime constraints ([Jepsen, Serializability, Informal](https://jepsen.io/consistency/models/serializable), [Jepsen, Strong Serializability, Informal](https://jepsen.io/consistency/models/strong-serializable)). Both Elle checkers and elle-cli default to `strict-serializable` when no model is passed ([list_append.clj `check`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/list_append.clj), [rw_register.clj `check`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/rw_register.clj), [cli.clj `opts`](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/src/elle_cli/cli.clj)).

Require analysis of the requested history and an explicit verdict. CLI exit 0 also covers unknown-only results, help output and a run with no history argument; `true` only means no anomaly prohibited by the selected models was found, and "Elle is not complete". Retain structured anomalies and witness explanations. The cycle-search limit is "Number of ms for searching a single SCC for a cycle", and plotting has separate limits; neither bounds the entire process ([cli.clj `opts`, `-main`](https://raw.githubusercontent.com/ligurio/elle-cli/3c2504815945cd4ab1b5cc0142d2fe206e1ee285/src/elle_cli/cli.clj), [txn.clj `result-map`](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/src/elle/txn.clj), [Elle README, Completeness](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/README.markdown)). Account execution, conversion, analysis and rendering separately within `bugfinding-campaign`'s authorized budget.

## Return inspectable evidence

Preserve original events, converted history, selected model/checker/build/configuration, raw verdict, dependency witness and actual replay attempts. Explain the contradiction from observed operations and justified edges, as Elle's witnesses explain "why it implies a contradiction"; Jepsen "recommends checking reported anomalies by hand". A cycle shows anomalous phenomena in every clean interpretation of the observation, not an implementation root cause or durability loss ([Elle, §§4.3.2 and 6](https://arxiv.org/abs/2003.10554v1), [Elle README](https://raw.githubusercontent.com/jepsen-io/elle/4e359e597c52938b0afebb8bc42273914d68a424/README.markdown)). Reduce only while retaining boundaries, provenance, uncertainty and the same supported anomaly; route reduction and attribution to `failure-reduction` and `evidence-based-triage`.

Return the guarantee tested, reached workload/dependency shapes, actual costs, explicit outcomes, witness paths and untested dimensions. For false-finding traps, read [common mistakes](references/common-mistakes.md). Invocation preserves the user's existing execution and publication authority.
