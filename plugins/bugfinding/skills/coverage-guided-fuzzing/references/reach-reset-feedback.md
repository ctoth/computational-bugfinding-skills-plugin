# Reach, reset and feedback

Use a finite pilot on an existing target. This diagnostic order is the pack's decision aid, not a mandatory new instrumentation framework.

| Observation | Next useful investigation |
|---|---|
| Feedback grows in driver parsing but intended library code is untouched | Read actual compile/link/module coverage; instrument the target owner, not only the harness; `-fsanitize=fuzzer-no-link` requests "just the instrumentation without linking" ([LLVM libFuzzer, Fuzzer Usage](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/llvm/docs/LibFuzzer.md)). |
| Most inputs stop at compression/format checks | Construct mutations in the relevant decoded representation through existing producer/encoder ownership; byte mutation of compressed data leaves "virtually all generated inputs to be invalid for `uncompress`". Retain malformed-input checks when they test a separate guarantee ([Google structure-aware fuzzing guide, Example: Compression](https://raw.githubusercontent.com/google/fuzzing/734e55f3cfed1adbb51bf6cb5c65b4c1197b7089/docs/structure-aware-fuzzing.md)). |
| A stable format reaches a hard comparison barrier | Try a fitting dictionary (for "multi-byte magic values") or matched ordinary/CmpLog build, then measure the changed reach ([LLVM libFuzzer, Dictionaries](https://raw.githubusercontent.com/llvm/llvm-project/635f30899dd0914fa89f0b3dc9a9e548e6d0ceec/llvm/docs/LibFuzzer.md), [AFL++ CmpLog](https://raw.githubusercontent.com/AFLplusplus/AFLplusplus/d0070729206a80a9af297b2341edd63f68fdac35/instrumentation/README.cmplog.md)). |
| A saved input passes alone but fails after a long run | Preserve prior sequence/state and compare real lifecycle/reset boundaries; Jazzer warns `PER_TEST` "can result in non-reproducible findings". Do not discard evidence after one fresh regression ([Jazzer Lifecycle implementation](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer/a4e09fbbc775d129ce61d5802e893160e31a6d40/src/main/java/com/code_intelligence/jazzer/junit/Lifecycle.java), [AFL++ persistent mode](https://raw.githubusercontent.com/AFLplusplus/AFLplusplus/d0070729206a80a9af297b2341edd63f68fdac35/instrumentation/README.persistent_mode.md)). |
| Many calls occur but useful operations skip | Track admitted inputs, actual operation/effect and property evaluation separately; coverage reports show "which code paths are being fuzzed and &mdash; more importantly &mdash; which aren't" ([Rust coverage](https://raw.githubusercontent.com/rust-fuzz/book/18cfe0e68cfee717392552d3511bac08458d2c01/src/cargo-fuzz/coverage.md)). |

## Worked persistent-fixture diagnosis

A JVM fuzz test initializes a world in `@BeforeEach`. Saved-input regression passes; discovery produces a delayed state-dependent failure. Read the actual annotation/lifecycle: default discovery (`PER_TEST`) runs `@BeforeEach` "once for each fuzz test", while regression goes "through the full JUnit lifecycle for every execution". Preserve the original input sequence and outputs, then establish whether the promised experiment requires isolated inputs or intentional stateful sequences. Use supported lifecycle/reset for the former; represent the sequence explicitly for the latter. Neither outcome by itself decides product versus harness blame ([Jazzer FuzzTest annotation](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer/a4e09fbbc775d129ce61d5802e893160e31a6d40/src/main/java/com/code_intelligence/jazzer/junit/FuzzTest.java), [Jazzer Lifecycle implementation](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer/a4e09fbbc775d129ce61d5802e893160e31a6d40/src/main/java/com/code_intelligence/jazzer/junit/Lifecycle.java)).

## Choose one lever against the observed barrier

A custom mutator may unlock a structured decoder but still fail every semantic prerequisite. Keep its representation, trimming and replay contract explicit; `AFL_CUSTOM_MUTATOR_ONLY` changes the search population, and a broken output-buffer contract means "afl-fuzz will crash when trying to free your buffers" ([AFL++ custom mutators](https://raw.githubusercontent.com/AFLplusplus/AFLplusplus/d0070729206a80a9af297b2341edd63f68fdac35/docs/custom_mutators.md)). Use `semantic-program-generation` or `stateful-property-testing` when successful execution needs types, identities, permissions or earlier operations.

A source-only receiving lane and a typed choice-byte generator need deliberate producer-based conversion. Go corpus entries "must match the fuzzing arguments exactly, in that order"; relabeling bytes as a source string does not convert the generated program. `corpus-evolution` owns compatible exchange ([Go fuzzing, Corpus file format](https://raw.githubusercontent.com/golang/website/a8b66266e226994e2ead51317bace3ee83cedab9/_content/doc/security/fuzz/index.md)).

Record the actual discovery mode, target/build differences, counters and omissions with retained artifacts. Use `harness-sensitivity` for representative violations through the same property. Reallocate with `bugfinding-campaign`; repetition of the same blocked lane is not itself a new search dimension.
