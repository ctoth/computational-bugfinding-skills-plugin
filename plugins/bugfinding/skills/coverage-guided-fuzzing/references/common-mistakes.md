# Common mistakes

Each row is wrong first, then right, then why.

| Wrong | Right | Why |
|---|---|---|
| “The fuzzer reports coverage, so the library is covered.” | Verify actual target instrumentation and visited paths, including fuzz-build feature forwarding. | cargo-fuzz feature options "control the `fuzz_targets` crate" until forwarded, and a coverage report shows which paths "aren't" fuzzed ([Rust Fuzz Book guide, Cargo features](https://raw.githubusercontent.com/rust-fuzz/book/18cfe0e68cfee717392552d3511bac08458d2c01/src/cargo-fuzz/guide.md), [Rust coverage](https://raw.githubusercontent.com/rust-fuzz/book/18cfe0e68cfee717392552d3511bac08458d2c01/src/cargo-fuzz/coverage.md)). |
| “JUnit passed, so we fuzzed it.” | Establish discovery mode (`JAZZER_FUZZ=1`) and the one selected fuzz test. | "By default, Jazzer operates in regression mode unless fuzzing mode is explicitly enabled" ([Jazzer README, Regression mode](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer/a4e09fbbc775d129ce61d5802e893160e31a6d40/README.md)). |
| “BeforeEach resets every mutated input.” | Read the discovery lifecycle and choose `PER_EXECUTION` or explicit reset where inputs must be isolated. | Default `PER_TEST` runs `@BeforeEach` "once for each fuzz test", unlike regression's per-execution lifecycle ([Jazzer FuzzTest annotation](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer/a4e09fbbc775d129ce61d5802e893160e31a6d40/src/main/java/com/code_intelligence/jazzer/junit/FuzzTest.java), [Jazzer Lifecycle implementation](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer/a4e09fbbc775d129ce61d5802e893160e31a6d40/src/main/java/com/code_intelligence/jazzer/junit/Lifecycle.java)). |
| “Use all comparison/custom-mutation options.” | Choose one lever against a measured bottleneck. | CmpLog needs "two versions of the instrumented target program", and custom mutation has buffer/trim constraints ([AFL++ CmpLog](https://raw.githubusercontent.com/AFLplusplus/AFLplusplus/d0070729206a80a9af297b2341edd63f68fdac35/instrumentation/README.cmplog.md), [AFL++ custom mutators](https://raw.githubusercontent.com/AFLplusplus/AFLplusplus/d0070729206a80a9af297b2341edd63f68fdac35/docs/custom_mutators.md)). |
| “Five minutes means five CPU-minutes.” | Identify what the selected limit counts and account wall/CPU/startup separately. | AFL++ `-V` is "(fuzz time only!)" ([AFL++ selected-ref CLI source, usage text](https://raw.githubusercontent.com/AFLplusplus/AFLplusplus/d0070729206a80a9af297b2341edd63f68fdac35/src/afl-fuzz.c)). |
| “`go test -timeout=8m` caps the fuzzing run.” | Bound discovery with `-fuzztime`, account for `-fuzzminimizetime`, and enforce any wall bound outside `go test`. | The test binary calls `m.stopAlarm()` before `runFuzzing(...)` ([Go testing.go `M.Run`, go1.27.3](https://raw.githubusercontent.com/golang/go/2aae1000ea1d4b28923b96db28acf4e3b99d6aff/src/testing/testing.go)). |
| “cargo fuzz coverage is another search campaign.” | Use it to measure an existing corpus, not to search. | It "runs the program _without fuzzing_ on the provided corpus" ([Rust coverage](https://raw.githubusercontent.com/rust-fuzz/book/18cfe0e68cfee717392552d3511bac08458d2c01/src/cargo-fuzz/coverage.md)). |
| “No Python coverage report means no code ran.” | Check whether the termination mode flushes coverage; use `-atheris_runs` for measurement. | "Coverage reports are only generated when your fuzzer exits gracefully" ([Atheris README, Visualizing Python code coverage](https://raw.githubusercontent.com/google/atheris/e36da74cf42b5834c4e31d7cabb58d796695d29f/README.md)). |
| “FuzzTest --fuzz_for bounds only my selected property.” | Use `--fuzz=SUITE.PROPERTY` with an outer bound, or accept that `--fuzz_for` runs every fuzz test in the binary. | `--fuzz_for=T` is documented as "Run all fuzz tests in fuzzing mode for `T` duration" ([FuzzTest flags](https://raw.githubusercontent.com/google/fuzztest/1b4e4f0e4c446aca4660c43a28ec1b8d893b6510/doc/flags-reference.md)). |
| “`npx jest` passed, so the Jazzer.js fuzz test fuzzed.” | Enable fuzzing mode (`JAZZER_FUZZ=1`) and select exactly one fuzz test. | The Jest default mode is `"regression"`, and "In _fuzzing_ mode, only one fuzz test can be run" ([Jazzer.js fuzzing settings, mode](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md)). |
| “ESM target on Node 18, and the run proceeds, so it is instrumented.” | Use Node >= 20.6 (>= 20.11 for bug detectors) or the Jest/Babel route, and check coverage reaches target modules. | "On older Node versions, ESM loading still works but modules are not instrumented" ([Jazzer.js fuzz targets and CLI, ESM support](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-targets.md)). |
| “`--sync` is faster, so use it everywhere.” | Use `--sync` only for wholly synchronous code. | "don't use this option if the code under test contains asynchronous parts" ([Jazzer.js fuzzing settings, sync](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md)). |
| “Jest `beforeEach` resets state for every mutated input.” | Reset with `registerBeforeEachCallback` or inside the target. | Jest fuzzing mode registers the campaign as one Jest test (inference from source, not executed) ([Jazzer.js Jest runner source, `fuzz.ts`](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/jest-runner/fuzz.ts), [Jazzer.js callbacks source](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/core/callback.ts)). |
| “Jazzer.js bug detectors are sanitizers, so native addon memory errors are covered.” | Fuzz native addon code in a native lane built with sanitizers. | The addon build sets `-DCOMPILER_RT_SANITIZERS_TO_BUILD=""` ([Jazzer.js CMakeLists](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/fuzzer/CMakeLists.txt)). |
| “A higher historical seed-selection yield predicts this run.” | Measure this lane and retain uncertainty. | Target, scheduler and preprocessing budget changed; the study assumed "t seconds to perform the data reduction" and one hypothesis was "false under the optimal scheduling" ([Rebert et al., pp.864,871,873](https://www.usenix.org/system/files/conference/usenixsecurity14/sec14-paper-rebert.pdf)). |
