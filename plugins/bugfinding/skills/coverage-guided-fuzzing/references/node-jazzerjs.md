# Node.js with Jazzer.js

Jazzer.js runs libFuzzer in the Node process. Babel inserts "coverage counters so the fuzzer can detect new code paths, and comparison hooks (for `==`, `!=`, etc.)" into JavaScript as it loads ([Jazzer.js architecture, Components and Interactions](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/architecture.md)). Browsers are "Out of scope", so browser application code has no coverage-guided route here (same source, Constraints).

## Select the route

The CLI form is `jazzer <fuzzTarget> <fuzzerFlags> [corpus...] [-- <fuzzingEngineFlags>]`; arguments after `--` "are forwarded to the internal fuzzing engine (`libFuzzer`)". The target module exports `fuzz`, "which takes a `Buffer` parameter"; `FuzzedDataProvider` reads typed values from it. "Directly executing fuzz targets written in TypeScript is **NOT** supported", but a transpiled module exporting `fuzz` works, and Jest fuzz tests may be TypeScript ([Jazzer.js fuzz targets and CLI, Creating a fuzz target, TypeScript, Running the fuzz target](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-targets.md)).

The Jest route uses `it.fuzz`. Its default mode is `"regression"`; discovery needs e.g. `JAZZER_FUZZ=1 npx jest tests.fuzz.js`. "In _fuzzing_ mode, only one fuzz test can be run"; otherwise "Jazzer.js will run the first test it finds", so select one with `--testNamePattern` ([Jazzer.js fuzzing settings, mode and JAZZER_FUZZ](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md), [Jazzer.js Jest integration, Executing Jest fuzz tests](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/jest-integration.md)).

## Check what is instrumented

The `--includes`/`--excludes` default "will include everything outside the `node_modules` directory. If either of these flags are set the default value for the other is ignored." Direct ESM instrumentation needs "Node.js >= 20.6. Function hooks (bug detectors) additionally require Node.js >= 20.11"; on older Node "ESM loading still works but modules are not instrumented". The Jest route converts ESM to CJS with Babel and works on any supported Node ([Jazzer.js fuzz targets and CLI, ESM support and parameter table](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-targets.md)). `--dryRun` will "Disable code instrumentation for fuzzing", so it gives no feedback ([Jazzer.js fuzzing settings, dryRun](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md)).

`--coverage` writes an Istanbul report "upon exit"; "If the fuzzer does not finish, no report will be generated". Bound the measuring run with `--mode=regression`, `-runs=1` or `-max_total_time=N`, and leave it off during discovery because of "the substantial overhead that it adds" ([Jazzer.js fuzzing settings, coverage](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md), [Jazzer.js fuzz targets and CLI, Coverage report generation](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-targets.md)).

## Async work and per-input reset

"The resolution of a `Promise`, returned by a fuzz target, is awaited before the next fuzzing input is provided"; a second callback parameter is awaited the same way, and calling it with an argument "indicates a failure" ([Jazzer.js fuzz targets and CLI, Fuzz target execution modes](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-targets.md)). For `--sync`: "don't use this option if the code under test contains asynchronous parts"; in sync mode the fuzzer "blocks the event loop" ([Jazzer.js fuzzing settings, sync](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md), [Jazzer.js native addon README](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/fuzzer/README.md)). Return or await everything the target starts. Unverified inference: un-awaited promises, timers or emitters can fail under a later input.

Jest fuzzing mode registers the whole campaign as one Jest test, while regression registers one test per input file plus `<empty>` ([Jazzer.js Jest runner source, `fuzz.ts`](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/jest-runner/fuzz.ts)). Jest `beforeEach` "Runs a function before each of the tests in this file runs" ([Jest Global API, beforeEach](https://raw.githubusercontent.com/jestjs/jest/72614448ecb9d16c58d6474b3091247c14a5c090/docs/GlobalAPI.md)). Inference, not executed: it therefore runs once per discovery campaign but once per input in regression, like JVM Jazzer `PER_TEST`. Reset per input with `registerBeforeEachCallback`/`registerAfterEachCallback`, which run "before or after each fuzz target invocation", or inside the target ([Jazzer.js callbacks source](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/core/callback.ts), [Jazzer.js API source](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/core/api.ts)).

## Oracles

An uncaught exception is a finding. Built-in bug detectors are "enabled by default" (`--disableBugDetectors=<pattern>` turns them off): command injection via `child_process`, path traversal via `fs` and `path`, prototype pollution, remote code execution via `eval` and `Function`, and SSRF for connections from `net`, `tls`, `http`, `http/2`, `https` and `dgram` unless permitted in a custom-hooks file. Prototype-pollution assignment instrumentation is off by default and has a stated "_Shortcoming:_" for added, deleted or modified prototype functions. `reportFinding` "escapes all try/catch blocks" but "will only report the first finding" ([Jazzer.js bug detectors](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/bug-detectors.md)). "Once a crash is found it logs it on the console and stops" ([Jazzer.js architecture, Components and Interactions](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/architecture.md)). A broad `catch` in the target hides ordinary exceptions, though not detector findings ([Jazzer.js finding source, `reportFinding`/`reportAndThrowFinding`](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/core/finding.ts)); catch only errors the input contract permits.

## Limits, seeds and artifacts

Use `--timeout` (milliseconds, default 5000); libFuzzer `-timeout` "will be ignored if passed via `fuzzerOptions`" ([Jazzer.js fuzzing settings, fuzzerOptions and timeout](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md)). The source passes it to libFuzzer as whole seconds rounded up, and appends `-runs=0` in regression mode ([Jazzer.js core options source, `optionDependentParams`](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/core/options.ts)). Without `-seed`, Jazzer.js prints "INFO: Using generated seed: <n>"; keep it. Exit code 77 is a finding, 78 an unexpected error ([Jazzer.js core source, `FuzzingExitCode`, `resolveInstrumentationSeed`](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/core/core.ts)).

CLI crash and timeout inputs "are stored in the current working directory with an auto-generated name" ([Jazzer.js fuzz targets and CLI, Running the fuzz target](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-targets.md)); the CLI `mode` text names a "regression directory" instead, an unresolved doc conflict. Without a corpus directory Jazzer.js "will not save any inputs other than crashes on exit"; listed files are run "once" and the process exits, e.g. `npx jazzer fuzz-file ./crash-abcdef0123456789` ([Jazzer.js fuzzing settings, corpus and mode](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/docs/fuzz-settings.md)). Jest fuzzing mode saves crashes into the test's seed directory via `-artifact_prefix` ([Jazzer.js Jest runner source, `fuzz.ts`](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/jest-runner/fuzz.ts)). Directory roles, replay coverage and merge belong to `corpus-evolution`.

## Native addons

The addon builds compiler-rt with `-DCOMPILER_RT_SANITIZERS_TO_BUILD=""` and stubs sanitizer symbols to "Suppress libFuzzer warnings" ([Jazzer.js CMakeLists](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/fuzzer/CMakeLists.txt), [Jazzer.js sanitizer stubs](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/fuzzer/shared/sanitizer_symbols.cpp)). Instrumentation is Babel over JavaScript, so a user's native addon gets neither sanitizer nor coverage from Jazzer.js (inference from these sources). Fuzz native addon code in a native lane ([native runners](native-runners.md)).

## Platform, floor and maintenance

The release workflow checks five prebuilt addons: linux x64/arm64, darwin x64/arm64, win32 x64 ([Jazzer.js release workflow](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/.github/workflows/release.yaml)); the README list omits Linux arm64 ([Jazzer.js README, Supported Architectures](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/README.md)). Without a matching prebuilt, install "falls back to compilation", which expects "CMake and the C++ toolchain" ([Jazzer.js native addon README](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/packages/fuzzer/README.md)). Published `@jazzer.js/core` 4.0.0 declares `"node": ">= 14.0.0"`, and `@jazzer.js/jest-runner` peers on `jest >=29.0.0` ([npm `@jazzer.js/core`](https://registry.npmjs.org/@jazzer.js/core), [npm `@jazzer.js/jest-runner`](https://registry.npmjs.org/@jazzer.js/jest-runner)); the monorepo root's `>= 20.11.0` ([Jazzer.js root package.json, engines](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/package.json)) covers developing Jazzer.js ([Jazzer.js PR workflow, unit-test note](https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/.github/workflows/run-all-tests-pr.yaml)). npm publishes went from 2.1.0 (2023-10-23) to 4.0.0 (2026-04-15) ([npm `@jazzer.js/core`](https://registry.npmjs.org/@jazzer.js/core)); "Releases v3.x.x were used by the commercial version and are therefore skipped" ([Jazzer.js v4.0.0 release](https://github.com/CodeIntelligenceTesting/jazzer.js/releases/tag/v4.0.0)). Check the installed version and its Jest compatibility before relying on these notes.
