### Contract record, before spending search compute

For the selected API and actual caller, record:

1. Input domain and representation: exact received bytes/bits, decimal parsing or binary conversion, shape/order/units and valid exceptional inputs. Distinguish an exact binary input from a physically measured quantity with uncertainty.
2. Required result: correctly rounded mathematical operation; specified sequence of rounded operations; bounded approximation; backward error/residual; interval enclosure; or an explicitly permitted set of outcomes. Extract the actual bound and rounding rule from the producer's contract. Do not promote a desirable mathematical identity to a product requirement.
3. Arithmetic environment: input/intermediate/output formats, compiler/version/options, CPU/architecture, selected library/backend, fusion/contraction policy, rounding mode and subnormal policy. Retain configuration differences as potential explanations until adjudicated.
4. Observation: result classification and sign, exact finite bits, documented flags/errors, plus any branch or persistent effect influenced by the value. A return-only metric can miss a numeric branch changing an effect.
5. Reference independence: different algorithm/library, specified exact arithmetic or validated enclosure; provenance for any shared dependency. A target rerun at the same precision is replay, not independent ground truth.

These are design requirements for a useful numerical experiment, inferred from FPGen's source-level high-precision comparison and its precision-operation caveat (paper pp.1268-1269), MPFR's model, and Herbie's platform/precondition model below.

### Choose a comparison with a named meaning

| Contract | Useful comparison | Failure interpretation and limit |
|---|---|---|
| Correct rounding of one supported operation | Independent reference correctly rounded to the requested format/mode, including range handling | Exact result bits under the contract; a broad tolerance would hide the defect. |
| Stepwise interpreter/compiler arithmetic | Reproduce the specified rounded operation graph and permitted fusion at each step | A final exact-real result is a different contract. Reassociation is not automatically valid. |
| Approximate numerical routine | Stated absolute/relative/componentwise/normwise or backward bound against an independent reference | Reject only a demonstrated violation of the bound on an in-domain input. |
| Validated enclosure | Prove target containment or a separation from a valid reference enclosure | Overlapping/wide intervals can be inconclusive; do not label overlap success or a defect. |
| Differential compiler/backend lane | Match specified semantics and compare the allowed outcome relation | A disagreement locates a candidate; different permitted arithmetic modes may explain it. |

NIST DLMF 1.2.8 (2026-09-15), [§3.1(v), equations3.1.8-3.1.11](https://dlmf.nist.gov/3.1#v), defines absolute error `|y-r|`, relative error `|y-r|/|r|` for nonzero reference `r`, and a separately named mollified measure. Thus denominator clamping changes the metric; name the changed contract instead of calling it relative error at zero. [§3.1(ii)](https://dlmf.nist.gov/3.1#ii) requires endpoint rounding for rigorous inclusion and excludes division by a zero-containing divisor interval. Exact fragment: “appropriate roundings of the end points”. Accessed2026-11-07; no DLMF executable or library is proposed.

Recommended inference: use absolute error near a reference zero only when the contract supplies an absolute scale; use relative error away from zero when the contract permits it; use an explicit combination only when justified by the API's required guarantee. Avoid computing the comparator in target precision if its subtraction, division or bound arithmetic can itself overflow, underflow or lose the decisive difference. Compare rigorous bounds or sufficient independent precision.

ULP distance needs a format, finite-value ordering, zero policy and boundary convention. A count of representable values is useful for correctly rounded output comparisons; it is not a universal physical error unit or a probability. Different binades have different spacing. Herbie's documentation defines its own transformed distance below; do not silently reuse its zero/NaN conventions.

For conditioning, distinguish input uncertainty from arithmetic error. An elementary derived example is exact summation `s=sum(x_i)`: if each component is perturbed by at most `eta*|x_i|`, triangle inequality gives `|delta s| <= eta*sum(|x_i|)`. When `s != 0`, relative sensitivity is bounded by `eta*sum(|x_i|)/|s|`; cancellation can make that factor large. This derivation is an interpretation, not a claim of an implementation error or a bound for an arbitrary algorithm. Even an ill-conditioned problem can have an implementation violating its own contract; conditioning is diagnostic, not a reason to dismiss every large error.

## MPFR: selected independent arithmetic reference, with boundaries

[MPFR4.2.2 manual](https://www.mpfr.org/mpfr-4.2.2/mpfr.html), §§2,3,4.2-4.6,5.3-5.5,5.11,5.13, accessed2026-11-07. Exact fragment: “The value stored in the destination variable is correctly rounded”. Most operations round to destination precision/mode; this is not a proof for an entire composition. `mpfr_can_round` requires a supplied approximation error bound; repeated precision agreement alone supplies no such proof. `mpfr_set_d`/`mpfr_get_d` support binary conversion, subject to documented type/rounding restrictions. MPFR has one NaN and no native subnormals. Its binary64 emulation example sets precision53, exponent bounds(-1073,1024), and propagates each operation's ternary result into `mpfr_subnormalize`; precision53 alone is insufficient. The library is LGPL3-or-later; GMP and a fitting C build are prerequisites. The manual's conditional link command is `cc -o version version.c -lmpfr -lgmp`. No build or target execution was performed.

Recommended inference: for a whole-expression exact-real contract, evaluate a proved outward enclosure with valid interval operations and domain handling, refining precision until its endpoints imply one target-format rounded value or a decisive bound violation. Preserve unknown when refinement cannot decide. MPFR's upward/downward modes are components for implementing justified interval operations, not an automatic interval wrapper: choose extrema for products/division, account for dependencies and split singular intervals. Increasing precision is a search budget, not license to pronounce an unstable reference exact. For a stepwise FP contract, retain per-operation rounding instead of replacing the computation with its real-arithmetic equivalent.

Separate classifications before scalar error arithmetic: finite, positive/negative infinity, NaN, positive/negative zero, normal/subnormal. Define which distinctions the target promises. A numeric `==` can conceal zero sign; a NaN can defeat ordinary ordered comparisons. MPFR's single-NaN model cannot establish payload/signaling-NaN preservation. Do not use it to prove a requirement outside that model. Record unmodeled flags/payloads as a reference limitation.

## Error-directed search: transfer the mechanism, not artifact assumptions

Guo and Rubio-González, *Efficient Generation of Error-Inducing Floating-Point Inputs via Symbolic Execution*, ICSE2020, pp.1261-1272, DOI10.1145/3377811.3380359, [author PDF](https://web.cs.ucdavis.edu/~rubio/includes/icse20.pdf). Read through paper-reader as twelve page images; local notes preserve the algorithm/equations/parameters/bibliography. Exact fragment, p.1271: “floating-point arithmetic does not satisfy associative and distributive laws”. No other paper quotation is needed in a draft.

The paper establishes an actionable distinction: conventional path coverage can saturate while error varies on the same path (pp.1262-1264). FPGen injects exponent-gap and cancellation predicates around additions/subtractions, then concretizes most components while symbolically searching selected operands. Generated inputs are evaluated separately for final result error; predicate hits are guidance, not the correctness oracle (pp.1265-1268). The selected empirical thresholds are not universal tolerances. Full study counts are historical benchmark results, not promised product yield. Its coverage-based baseline and bounded numeric ranges do not establish completeness (pp.1268-1271).

Skill inference for an existing property/fuzz harness:

1. Build a sensitive contract comparator and classify outcomes as confirmed violation, permitted, reference-inconclusive, out-of-domain, or harness failure. Exercise the real producer before using a surrogate expression.
2. Seed meaningful bit patterns: signed zeros, smallest/largest relevant subnormals/normals, adjacent values around specified domain/rounding/overflow boundaries, equal/opposite magnitudes, sparse/dense mantissas and operand exponent gaps. Generate dependent array/matrix inputs respecting actual invariants rather than treating every component independently.
3. Mix existing coverage search with numeric fitness such as proved bound margin, ULP mismatch, cancellation predicate or exponent gap. Keep the cheap score separate from the independent final oracle. Retain divergent numeric behaviors even when code coverage is unchanged.
4. For expensive references, use staged evaluation: cheap domain/classification/fitness, then independent refinement of promising candidates. Report inconclusive references and precision/time budgets rather than discarding those inputs silently.
5. Spend additional compute on neighborhoods and regimes around confirmed candidates: adjacent representables, exponent strata, operand ordering, permitted backend/configuration combinations. Preserve actual inputs and selected environment; a seed alone cannot reproduce time-bounded search.

## Reproduction, meaningful reduction and sensitivity

Recommended inference from the above reference/search limits:

- Save exact binary inputs and format, the raw producer invocation, domain/schema, original and reference outputs with classifications, proved bounds or interval endpoints, reference precision/mode, target/compiler/library/configuration identity and any diagnostic trace. Save discarded/inconclusive candidates separately with cause.
- Minimize actual input structure and numeric parameters while requiring the *same contract violation*. Remove array/matrix elements only if shape, normalization, ordering or positive-definiteness constraints still hold. Preserve real caller reachability and branch/effect observations.
- Try exponent scaling and mantissa simplification, adjacent representables and shrinking cancellation pairs together. Keep both the original and reduced exact bits. Ordinary shrinking toward zero can destroy the exponent-gap, cancellation or subnormal regime; decimal pretty-printing can change the test input.
- Preserve reference validity while reducing. A smaller input that makes the reference overflow, produce a wide interval or violate preconditions is not a smaller confirmed bug. A different failure classification starts a separately adjudicated candidate.
- Sensitivity controls must traverse the actual comparator and producer boundary: selected nearby reference values inside/outside the permitted error bound; incorrect rounding direction or one representable neighbor where the contract excludes it; sign-zero and permitted nonfinite cases; a deliberately inconclusive enclosure. These are planned controls, not executed results. A comparator that calls `abs(NaN)>epsilon` and reports pass is invalid.

## Advanced worked scenarios for the drafter

1. **Whole-sum accuracy versus stepwise FP semantics.** Generate large opposite-magnitude values plus a small residual, preserve exact bits and ordering, and score cancellation. If the API promises a bounded approximation of the mathematical sum, compare to an independently established sum/reference bound; if it promises ordinary sequential rounded addition, a different real sum is not itself a bug. Reduce operand pairs jointly while preserving the contract-specific excess. FPGen pp.1263-1268 motivates the search; this scenario is illustrative.
2. **Subnormal boundary.** Select finite inputs on both sides of a specified underflow boundary, including neighbors and signs. A reference with binary64 precision but an unrestricted exponent range can produce a spurious mismatch. Match the intended target range/subnormal policy or label the comparison unsupported, then distinguish permitted underflow from a violated rounded-result rule. MPFR manual§5.13 supports the model warning; no target behavior was observed.
3. **Small-domain repair search with regional regression.** Extract a pure expression from a real caller, explicitly model actual input preconditions and platform, run Herbie only in a fitting already-authorized environment, and inspect local error regimes. Independently test proposed replacements across required special values and boundary neighborhoods. Average sampled improvement does not justify merging a replacement that violates the application's worst-case bound. Herbie's error/options/input docs support the constraints.
4. **Precision agreement that remains unproved.** Two high-precision replays agree on an output near a target rounding midpoint. Preserve the candidate; use a justified enclosure/error bound and refine until decisive. If still undecidable at the budget, record reference-inconclusive. A fixed arbitrary precision or `long double` reference is not universal evidence of correct rounding. This is an inference from MPFR's operation-level contract and `mpfr_can_round` precondition.
