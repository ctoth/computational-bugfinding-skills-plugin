### R2. Jazzer.js crash minimization (failure-reduction)

Pin: `CodeIntelligenceTesting/jazzer.js` `f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1` (same pin as `research-js-fuzzing-corpus.md`). Raw base `https://raw.githubusercontent.com/CodeIntelligenceTesting/jazzer.js/f23bc5aeb7a6d50cd6256cfc3be44b868da5e7b1/`.

- No Jazzer.js doc mentions minimization: grep for `minimi` in `docs/fuzz-settings.md`, `docs/fuzz-targets.md`, `docs/jest-integration.md` returns nothing.
- Source accommodates the libFuzzer flag: `packages/core/options.ts:517-518`: "// These flags cause libFuzzer to spawn subprocesses." `const SUBPROCESS_FLAGS = ["fork", "jobs", "merge", "minimize_crash"];`. `spawnsSubprocess` (lines 520-527) matches `-minimize_crash=<non-zero>`; then `prepareLibFuzzerArg0` (lines 504-515) writes a wrapper script (`.sh`, or `.bat` on win32, lines 544-558) re-invoking the same `jazzer` argv so libFuzzer can spawn child processes. libFuzzer engine flags are passed after `--` (CLI shape `jazzer <fuzzTarget> <fuzzerFlags> [corpus...] [-- <fuzzingEngineFlags>]`, `docs/fuzz-targets.md:224`, per J1 of the fuzzing report).
- In-repo tests: the tree has `tests/fork_mode/` but no test path containing `minimi` (GitHub trees API). Minimization is therefore source-accommodated, undocumented and untested in-repo.
- Independent agreement: `research-js-fuzzing-corpus.md` J5 (lines 77-83) reaches the same finding at the same pin. Division of work: that report covers `-merge=1` and treats crash minimization as a corpus operation; witness-preserving shrinking and replay against the selected predicate belong here.
- Inference (command composed from the two sources above, not executed): `npx jazzer <fuzzTarget> <crash-file> -- -minimize_crash=1 -runs=<N>` (or `-max_total_time=<s>`, which the existing libFuzzer recipe already requires to bound attempts). The minimized input must be replayed with `npx jazzer <fuzzTarget> <reduced-file>` (direct inputs "run them once and exit", `docs/fuzz-settings.md:72-78`) against the selected predicate, because libFuzzer minimizes toward any crash.
- Regression mode adds `-runs=0` (`options.ts:486-489`); every run also appends `-timeout=<ceil(timeout/1000)>` and `-handle_int=0 -handle_term=0 -handle_segv=0` (`options.ts:490-494,431-433`). Inference: `-handle_segv=0` means a native addon segfault is not reported through libFuzzer's handler.

## Common mistakes with evidence

- **M1 (symbolic).** Counting ExpoSE `[!]` entries or its exit code as bugs. Evidence: `Center.js:163-197` adds "Exit code non-zero" and analyser "fatal error" to the same error list; `Distributor.js:114` sets `process.exitCode = errors`.
- **M2 (symbolic).** Treating `expoSE replay` as native confirmation. Evidence: `scripts/play` runs Jalangi2 with `--analysis bin/Analyser.js`.
- **M3 (symbolic).** Selecting ExpoSE for modern/TS/ESM/async code without running it on the target. Evidence: Babel 6 `es2017`/`es2015` presets and `acorn` `ecmaVersion: 6` (fork `esnstrument.js:38-41,1881`); no promise/async/ESM test in the tree.
- **M4 (reduction/triage).** Using retries to "confirm" a flaky failure, or reading "flaky" as passing. Evidence: Playwright retry runs in a new worker and browser (`test-retries-js.md:36`); `failOnFlakyTests` default false; `jest.retryTimes` logs earlier errors only with `logErrorsBeforeRetry`.

- **M6 (reduction).** Accepting a Jazzer.js/libFuzzer (or Vitiate) minimized crash without replaying it against the selected predicate. Evidence: libFuzzer minimizes "the provided crash input" (existing `tool-recipes.md:76`); Jazzer.js minimization is undocumented (R2).
- **M7 (reduction).** Running Shrink Ray with defaults on an agent host. Evidence: LLM mode "enabled by default" with a 2.7 GB model download (`README.md:108-112`).
- **M8 (triage).** Handing off a Node diagnostic report or trace unredacted. Evidence: `environmentVariables` included by default (`report.md`, `--report-exclude-env`); trace `sources` default true and DOM snapshots "record network activity" (`class-testoptions.md:719-723`).
