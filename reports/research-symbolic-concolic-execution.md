- pp.3-4: symbolic execution forks feasible branches, checks dangerous operations and solves path conditions into concrete inputs. Native replay detects implementation/model/nondeterminism problems; the paper explicitly reports practical false positives despite its intended exactness. A solver-produced input is not independent executable confirmation.
- pp.5-7: solver cost and state explosion need separate diagnosis. Expression/constraint simplification, independence, counterexample caching and diverse state scheduling address different costs. The historical internal optimizations are not new plugin infrastructure to reimplement.
- pp.7-8: a model of environmental reads must propagate writes consistently; concrete descriptors, symbolic files, metadata and failing syscalls affect reachability. The authors' low-level syscall modeling avoids copying a whole libc model, but still narrows real OS behavior. Native replay reconstructs actual files/pipes/arguments and is especially difficult for modeled failing syscalls.
- pp.9-12: results depend on chosen argument/file bounds, library coverage accounting and completed versus live states. The historical paper reports one-hour runs and large coverage gains, but these are not tool defaults or expected yields for a new target. Only low-level checks/user assertions are automatic; more coverage is not expected-output correctness.
- pp.12-14: same-input equivalence assertions can turn semantic or differential properties into solver queries, but results cover only actually explored paths/model assumptions. The paper explicitly excludes unseen paths and contains memory-address nondeterminism caveats. Reuse actual target/reference paths rather than copy production behavior into a solver-only imitation.
- pp.14-15: a real target-linked HiStar driver explores bounded syscall sequences and finds an overflow condition; its missing many-object states limits coverage. This illustrates varying state/sequence/input dimensions and native reproduction, not a drop-in modern Go/KLEE route.

## Method decisions that buy useful evidence

These are plugin design choices derived from S1-S7 and the read paper, not new frameworks or universal optimal strategies.

1. Inspect the real target producer/build and find a measured missing path: checksums, nested arithmetic/range conditions, state-dependent checks or structured fields. More solver work is not useful when the intended operation is outside the harness or the input cannot influence it. Choose a fitting source-supported target, not a rewrite of production behavior into another language.
2. Separate symbolic inputs from legal-domain assumptions, environmental models and the violated property. Keep actual field widths/endian/length/initial-state constraints. A success stub or an assumption equal to the property under test can erase all violating paths. Do not hide unsupported instructions or infeasible assumptions as completed healthy tests.
3. Start with a small meaningful boundary and enough concrete setup to preserve public semantics. Add symbolic state/files/operations only when they reach a real omitted behavior. Removing initialization to make the solver faster can remove the real bug.
4. Diagnose path explosion, query cost and environmental concretization separately. A short compatible pilot can compare search policies or seed-guided concolic handoff. Preserve unresolved/timed-out/pruned/unsupported work; a solver Unknown is not UNSAT, and a bounded no-candidate run is not an absence proof.
5. Feed generated candidates to the actual real-target oracle with compatible build/state/environment. A changed source/optimization/sanitizer can make behavior differ; retain both execution identities. A model-induced assertion does not establish a product bug until its assumptions and native witness hold.
6. Retain exact original inputs, constraints/queries where relevant, generated artifacts and provenance, model/solver/compiler/runtime identities, limits, warnings, completed/unfinished state evidence and actual replay attempts. Reduce while preserving valid domain, setup and the same violation; use existing reduction/triage owners.

No generic solver adapter, model-copy service, symbolic fork for every runtime, mandatory cloud environment or new cache layer is justified. Existing KLEE/SymCC APIs should be used only where their real target linkage is established.

## Advanced worked scenarios

All are illustrative designs, not executed tests or observed Barn defects.

- **Rare field guard before semantic state mutation.** An existing native producer reads a bounded record, validates a relationship between fields, then changes protected state. Symbolicize those actual fields and preserve valid setup/domain; assert the documented state property after the real operation. Reproduce a candidate through the native producer and same effect oracle. A copied simplified implementation can satisfy a different branch and is not the target.
- **Concretized library masks the path.** Input crosses an uninstrumented C++ container/library or a KLEE external call before the branch. Missing symbolic influence explains an unproductive search even if the solver runs. Use a fitting maintained instrumented dependency/model if authorized; otherwise retain the limitation. Increasing solver time or allowing arbitrary externals does not repair the lost semantics.
- **Model creates an impossible I/O failure.** Symbolic environment produces an assertion only after a specific syscall fails. Retain file contents, metadata, call sequence, error model and actual failure boundary. A plain native replay with no injected failure can miss it; do not count the model result as native confirmation or dismiss the original trace. Establish a supported real failure mechanism or mark it model-bound.
- **Hybrid queue finds inputs but no bugs.** Matched symbolic and sanitizer/semantic builds exchange cases. Measure generated, accepted, actual oracle-evaluated, rejected, pruned and replayed candidates plus total solver/replay cost. New queue files can be useful reach evidence but are not confirmed unique defects. A helper's fixed attempt timer does not bound the whole run.
- **Unsupported Go runtime.** Barn's existing Go fuzz/structured/differential/history lanes already provide strong search. No inspected tool here establishes native symbolic execution of its actual runtime. Report that fact and choose a compatible existing method; do not port VM logic to C solely to obtain a KLEE result. That would change the producer and violate source ownership.
